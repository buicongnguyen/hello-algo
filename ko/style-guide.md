# Hello Algo 한국어 문체 지침

버전: `v0.2-draft`

## 대상 독자

기초 프로그래밍은 알지만 수학 표기나 알고리즘 분석에 익숙하지 않은 자료구조·알고리즘 입문자를 대상으로 씁니다.

## 원칙

1. 기술적 정확성을 우선하되, 읽기 어려운 직역을 정확성의 근거로 삼지 않습니다.
2. 논리 관계를 잃지 않는 범위에서 짧고 능동적인 문장을 사용합니다.
3. “만약”, “오직”, “적어도”, “최대”, “평균적으로”, “최악의 경우” 같은 조건과 한정을 생략하지 않습니다.
4. 조건부 설명을 보편적인 단정으로 바꾸지 않습니다.
5. `glossary.md`의 용어를 사용하고, 필요하면 첫 등장에 영어를 괄호 안에 병기합니다.
6. 수식, 변수, 기호와 인라인 코드는 원문 표기를 유지합니다.
7. 그림의 대체 텍스트는 학습자가 관찰해야 할 관계나 변화를 설명합니다.
8. API, 함수명, 클래스명, 키워드와 코드 식별자는 번역하지 않습니다.

## 문체와 호칭

- 설명은 `-합니다 / -됩니다`체로 통일합니다.
- 함께 추론하는 대목에는 “우리는”을 절제해 사용합니다.
- 직접 지시는 필요할 때만 “여러분” 없이 동작 중심으로 씁니다.
- 주어가 분명할 때 불필요한 대명사를 반복하지 않습니다.

## 제목과 문장부호

- 제목 끝에는 마침표를 붙이지 않습니다.
- 한국어 문장부호를 사용하되 코드와 수식 안의 ASCII 문자는 유지합니다.
- 인라인 코드 뒤의 문장부호는 코드에 포함되지 않는 한 코드 바깥에 둡니다.
- 영문 약어는 처음 등장할 때 풀어 쓰거나 한국어 설명을 함께 제공합니다.

## 편집 예

| 피할 표현 | 권장 표현 | 이유 |
| --- | --- | --- |
| 알고리즘은 문제를 푸는 단계이다. | 알고리즘은 문제를 해결하기 위한 유한한 단계의 집합입니다. | 정의의 범위를 분명히 함 |
| 이것은 빠르다. | 입력 크기가 커질 때 실행 단계 수가 선형으로 증가합니다. | “빠름”의 기준을 설명 |
| 항상 이진 탐색을 쓴다. | 데이터가 정렬되어 있고 중간 원소에 효율적으로 접근할 수 있을 때 이진 탐색을 사용합니다. | 적용 조건을 보존 |
| 배열은 O(1)이다. | 배열의 인덱스 접근은 $O(1)$ 시간에 수행됩니다. | 대상 연산을 명시 |

## 수식과 복잡도

- `$O(n \log n)$`, `$O(1)$ 같은 LaTeX 표현을 유지합니다.
- 실제 실행 시간과 시간 복잡도를 구분합니다.
- 어떤 알고리즘이 “더 빠르다”고 할 때는 입력 크기, 데이터 조건 또는 증가 차수를 밝힙니다.
- 수식과 설명이 어긋나지 않도록 수학 변수명을 임의로 번역하지 않습니다.

## 그림과 편집 변경

- 원본 그림을 유지하고 대체 텍스트와 캡션을 한국어로 작성합니다.
- 이 작업이 Hello Algo 영어판에서 파생된 커뮤니티 번역임을 명시합니다.
- 예제, 그림 또는 논증을 원문과 다르게 바꾸면 풀 리퀘스트와 릴리스 노트에 이유를 기록합니다.
