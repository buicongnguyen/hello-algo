# 이진 탐색 경계

## 왼쪽 경계 찾기

!!! question

    길이가 $n$이고 오름차순이며 중복될 수 있는 배열 `nums`가 주어집니다. 가장 왼쪽 `target`의 인덱스를 반환하세요. 목표가 없으면 $-1$을 반환합니다.

이진 탐색 삽입 위치를 떠올려 보세요. 반복이 끝나면 포인터 $i$가 가장 왼쪽 `target`을 가리킵니다. **따라서 삽입 위치 찾기는 본질적으로 가장 왼쪽 `target`의 인덱스를 찾는 일입니다**.

삽입 위치 함수를 그대로 재사용할 수 있지만 배열에 `target`이 없을 수 있어 두 경우를 처리해야 합니다.

- 삽입 위치 $i$가 배열 범위 밖입니다. 예를 들어 목표가 모든 원소보다 큽니다.
- `nums[i]`가 `target`과 다릅니다. 즉 삽입 위치가 기존 두 값 사이입니다.

두 조건 중 하나면 $-1$을 반환합니다. 배열을 읽기 전에 범위를 먼저 확인하여 범위 밖 접근을 막아야 합니다.

```python
# 잠긴 원문의 왼쪽 경계 구현이 삽입됩니다.
```

목표와 같은 원소를 만났을 때 바로 반환하지 않는 것이 핵심입니다. 계속 왼쪽으로 범위를 좁히고 후보 위치를 기록하여, 앞쪽에 같은 목표가 더 없음을 증명할 때까지 탐색합니다.

## 오른쪽 경계 찾기

가장 오른쪽 `target`은 어떻게 찾을까요? 가장 직접적인 방법은 `nums[m] == target` 분기를 바꾸어 목표를 만나도 왼쪽이 아니라 오른쪽을 계속 찾는 것입니다. 탐색 구간의 불변식을 바탕으로 구현할 수 있습니다.

다음은 조금 더 기발한 두 변환 방법입니다.

### 왼쪽 경계 찾기 재사용

가장 왼쪽 `target`을 찾는 함수로 오른쪽 경계를 찾을 수 있습니다. **가장 오른쪽 `target` 찾기를 가장 왼쪽 `target + 1` 찾기로 바꿉니다**.

탐색 후 $i$는 존재한다면 가장 왼쪽 `target + 1`을, $j$는 가장 오른쪽 `target`을 가리킵니다. 따라서 $j$를 반환할 수 있습니다.

![오른쪽 경계 찾기를 왼쪽 경계 찾기로 변환](binary_search_edge.assets/binary_search_right_edge_by_left_edge.png)

삽입 위치 함수는 $i$를 반환하므로 $1$을 빼서 $j$를 얻습니다.

```python
# 잠긴 원문의 오른쪽 경계 구현이 삽입됩니다.
```

변환한 뒤에도 결과가 실제 목표를 가리키는지 확인해야 합니다. 모든 원소가 목표보다 작거나 배열에 목표가 없으면 후보 인덱스가 유효하지 않을 수 있습니다.

### 원소 찾기로 변환

배열에 `target`이 없으면 두 포인터 $i$와 $j$는 각각 `target`보다 큰 첫 원소와 작은 마지막 원소를 가리킵니다.

따라서 배열에 절대 없는 값을 만들어 두 경계를 찾을 수 있습니다.

- 가장 왼쪽 `target`: `target - 0.5`를 찾고 포인터 $i$를 반환합니다.
- 가장 오른쪽 `target`: `target + 0.5`를 찾고 포인터 $j$를 반환합니다.

![경계 찾기를 존재하지 않는 원소 찾기로 변환](binary_search_edge.assets/binary_search_edge_by_element.png)

코드는 연습문제로 남기지만 다음을 주의해야 합니다.

- 문제의 배열에는 소수가 없으므로 새 탐색 값과 같은 경우를 처리할 필요가 없습니다.
- 소수를 도입하므로 함수의 `target` 형식을 부동소수점으로 바꾸어야 합니다. Python은 명시적으로 바꾸지 않아도 됩니다.

이 변환은 `target ± 0.5` 같은 중간 값이 유효한 배열 원소와 겹치지 않고 정밀도 문제를 일으키지 않는다고 데이터 영역이 보장할 때만 안전합니다. 제품 코드에서는 경계를 직접 갱신하는 변형이 더 일반적입니다.
