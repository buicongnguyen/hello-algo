# 이진 탐색

<u>이진 탐색</u>은 분할 정복을 바탕으로 하는 효율적인 탐색 알고리즘입니다. 정렬된 데이터의 순서를 이용하여 매 반복마다 탐색 범위를 절반으로 줄이고, 목표 원소를 찾거나 범위가 빌 때까지 계속합니다.

!!! question

    길이가 $n$이고 원소가 오름차순이며 중복되지 않는 배열 `nums`가 주어집니다. 배열에서 `target`을 찾아 인덱스를 반환하세요. 원소가 없으면 $-1$을 반환합니다. 예시는 아래와 같습니다.

![이진 탐색 예시 데이터](binary_search.assets/binary_search_example.png)

먼저 두 포인터 $i = 0$과 $j = n - 1$을 배열의 첫 원소와 마지막 원소에 둡니다. 두 포인터는 탐색 구간 $[0, n - 1]$을 나타냅니다. 대괄호는 양쪽 경계를 모두 포함하는 닫힌 구간임을 뜻합니다.

다음 두 단계를 반복합니다.

1. 가운데 인덱스 $m = \lfloor {(i + j) / 2} \rfloor$을 계산합니다. 여기서 $\lfloor \: \rfloor$은 내림입니다.
2. `nums[m]`과 `target`을 비교하여 세 경우 중 하나를 처리합니다.
    1. `nums[m] < target`이면 목표는 $[m + 1, j]$에만 있을 수 있으므로 $i = m + 1$로 둡니다.
    2. `nums[m] > target`이면 목표는 $[i, m - 1]$에만 있을 수 있으므로 $j = m - 1$로 둡니다.
    3. `nums[m] = target`이면 목표를 찾았으므로 인덱스 $m$을 반환합니다.

배열에 목표가 없으면 두 경계가 서로 지나쳐 탐색 구간이 비게 됩니다. 이때 $-1$을 반환합니다.

이 과정의 핵심 불변식은 “목표가 배열에 존재한다면 현재 닫힌 구간 안에 있다”입니다. 비교가 끝날 때마다 가운데 원소와 답이 될 수 없는 한쪽 구간을 함께 제외합니다. 따라서 이미 버린 구간을 다시 확인하지 않아도 되고, 두 경계가 교차하면 목표가 없다는 결론을 안전하게 내릴 수 있습니다.

## 구간 표현 방법

닫힌 구간 외에 “왼쪽 닫힘, 오른쪽 열림” 구간 $[0, n)$도 자주 사용합니다. 왼쪽 경계는 포함하고 오른쪽 경계는 포함하지 않습니다. 이 표현에서 $[i, j)$는 $i = j$일 때 빕니다.

같은 기능을 이 구간 표현으로 구현할 수 있습니다.

```python
# 잠긴 원문의 왼쪽 닫힘·오른쪽 열림 이진 탐색 구현이 삽입됩니다.
```

두 표현은 초기화, 반복 조건, 구간 축소 방식이 모두 다릅니다. 중요한 것은 한 규칙을 선택하고 알고리즘 전체에서 그 불변식을 일관되게 지키는 것입니다.

닫힌 구간에서는 왼쪽 경계 $i$와 오른쪽 경계 $j$가 모두 탐색 범위에 속하므로 두 축소 연산이 대칭적입니다. 이 방식은 확인하기 쉽고 하나 차이 오류가 적어 처음 구현할 때 권장됩니다.

## 장점과 한계

이진 탐색은 시간과 공간 효율이 모두 좋습니다.

- **높은 시간 효율**: 데이터가 많을 때 로그 복잡도의 이점이 큽니다. 예를 들어 $n = 2^{20}$이면 선형 탐색은 최대 $2^{20} = 1048576$개를 살펴보지만, 이진 탐색은 약 $\log_2 2^{20} = 20$번만 반복합니다.
- **추가 메모리가 거의 필요 없음**: 해시 탐색처럼 별도 구조를 만들지 않고 반복 버전은 경계 인덱스만 유지합니다.

그러나 모든 상황에 적합하지는 않습니다.

- **데이터가 정렬되어야 합니다.** 정렬되지 않은 입력을 한 번 찾기 위해 정렬하는 것은 보통 이득이 없습니다. 정렬 자체가 $O(n \log n)$으로 한 번의 선형 탐색보다 비싸기 때문입니다. 삽입이 잦으면 정렬 배열을 유지하기 위한 올바른 위치 삽입도 $O(n)$이 걸립니다.
- **효율적인 임의 접근이 필요합니다.** 가운데 원소로 계속 점프하므로 배열에 적합합니다. 연결 리스트에서는 가운데 노드를 찾기 위해 연결을 순서대로 따라가야 하므로 이점이 사라집니다.
- **작은 데이터는 선형 탐색이 더 나을 수 있습니다.** 선형 탐색 한 번은 비교 하나면 되지만 이진 탐색은 가운데 계산, 여러 비교, 경계 갱신을 수행합니다. $n$이 작으면 상수 비용 때문에 선형 탐색이 더 빠를 수 있습니다.

구체적으로 선형 탐색의 한 반복은 대체로 비교 한 번이면 충분합니다. 이진 탐색의 한 반복은 가운데를 계산하는 덧셈과 나눗셈, 한 번에서 세 번의 비교, 경계를 옮기는 덧셈이나 뺄셈을 포함합니다. 그래서 점근 복잡도가 더 좋아도 아주 작은 입력에서는 더 많은 단위 연산을 수행할 수 있습니다.

데이터가 이미 정렬되어 있고 인덱스 접근을 지원하며, 탐색 횟수가 충분해 순서 유지 비용을 상쇄할 때 이진 탐색을 선택하는 것이 좋습니다.
