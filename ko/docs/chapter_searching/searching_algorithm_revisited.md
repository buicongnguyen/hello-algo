# 탐색 알고리즘 돌아보기

<u>탐색 알고리즘</u>은 배열, 연결 리스트, 트리, 그래프와 다른 자료구조에서 조건을 만족하는 원소 또는 원소 집합을 찾습니다.

구현 방식에 따라 두 그룹으로 나눌 수 있습니다.

- **자료구조를 순회하여 목표를 찾기**: 배열, 연결 리스트, 트리, 그래프 순회가 여기에 속합니다.
- **데이터의 조직 방식이나 알려진 정보를 이용해 효율적으로 조회하기**: 이진 탐색, 해시 조회, 이진 탐색 트리 조회가 여기에 속합니다.

각 기법은 앞 장에서 소개되었습니다. 여기서는 전처리, 질의, 갱신, 메모리 비용을 기준으로 체계적으로 비교합니다.

## 완전 탐색

완전 탐색은 자료구조의 원소를 차례로 순회하여 목표를 찾습니다.

- **선형 탐색**은 배열과 연결 리스트에 적용합니다. 한쪽 끝에서 시작해 목표를 만나거나 구조 끝에 도달할 때까지 각 원소를 읽습니다.
- **너비 우선과 깊이 우선 탐색**은 트리와 그래프 순회 전략입니다. BFS는 가까운 곳에서 먼 곳으로 층별 이동하고, DFS는 한 가지를 끝까지 탐색한 뒤 되돌아가 다른 가지를 시도합니다.

장점은 단순하고 일반적이며 **데이터 전처리나 보조 구조 구축이 필요 없다는 점**입니다. 한 번만 찾거나 데이터가 작거나, 갱신이 매우 잦아 인덱스 유지 비용이 큰 경우에 적합합니다.

하지만 **시간 복잡도는 보통 $O(n)$**이며 $n$은 원소 수입니다. 데이터가 크고 질의가 많으면 매번 전체 구조를 다시 읽는 비용이 큽니다.

완전 탐색은 데이터 배치에 대한 특별한 가정이 없으므로 정렬되지 않은 입력에도 그대로 적용할 수 있습니다. 또한 값이 추가되거나 삭제되어도 별도의 색인을 다시 만들 필요가 없습니다. 이런 일반성은 준비 비용을 줄여 주지만, 같은 데이터를 반복해서 찾는 상황에서는 매 질의마다 처음부터 순회하는 비용을 치르게 합니다.

## 적응형 탐색

적응형 탐색은 정렬 순서 같은 데이터의 속성을 이용하여 목표가 있을 수 없는 영역을 빠르게 제거합니다.

- **이진 탐색**은 정렬 순서를 이용해 매 반복 범위를 절반으로 줄이며 배열처럼 임의 접근이 가능한 구조에 적합합니다.
- **해시 조회**는 데이터를 해시 테이블의 키-값으로 저장해 키의 위치를 거의 직접 찾습니다.
- **트리 탐색**은 이진 탐색 트리나 균형 트리에서 노드 값을 비교하여 한쪽 가지를 빠르게 제거합니다.

이 방법들은 매우 효율적이며 **$O(\log n)$ 또는 평균 $O(1)$까지 달성할 수 있습니다**.

대신 **대개 전처리나 보조 구조가 필요합니다**. 이진 탐색은 정렬 배열, 해시 조회는 해시 테이블, 트리 탐색은 트리 관계를 만들고 유지해야 합니다. 삽입, 삭제, 균형 복원에도 시간과 메모리가 듭니다.

따라서 적응형 탐색의 빠른 질의는 무료가 아닙니다. 정렬에는 비교와 원소 이동이 필요하고, 해시 테이블은 버킷 공간과 충돌 처리가 필요하며, 균형 트리는 삽입과 삭제 뒤 회전이나 높이 정보 갱신이 필요합니다. 조회 전에 지급한 구축 비용과 각 갱신에서 지급하는 유지 비용을 여러 질의가 나누어 부담한다고 볼 수 있습니다.

!!! tip

    적응형 탐색은 흔히 조회 알고리즘이라고도 하며 특정 자료구조에서 목표 원소를 빠르게 가져오는 데 사용됩니다. 높은 질의 효율은 사전 구성 또는 갱신 과정에서 수행한 데이터 조직 작업에서 나옵니다.

## 탐색 방법 선택

크기 $n$인 데이터에 선형, 이진, 트리, 해시 탐색을 선택할 수 있습니다. 그림은 네 방법의 원리를 비교합니다.

![여러 탐색 전략](searching_algorithm_revisited.assets/searching_algorithms.png)

표는 효율과 특징을 요약합니다. 트리 값은 균형 구조를 가정하고, 해시 테이블은 해시 함수와 충돌 처리가 잘 작동할 때의 평균 복잡도입니다.

| 특성 | 선형 탐색 | 이진 탐색 | 트리 탐색 | 해시 조회 |
| --- | --- | --- | --- | --- |
| 원소 찾기 | $O(n)$ | $O(\log n)$ | $O(\log n)$ | $O(1)$ |
| 원소 삽입 | $O(1)$ | $O(n)$ | $O(\log n)$ | $O(1)$ |
| 원소 삭제 | $O(n)$ | $O(n)$ | $O(\log n)$ | $O(1)$ |
| 추가 공간 | $O(1)$ | $O(1)$ | $O(n)$ | $O(n)$ |
| 전처리 | 없음 | 정렬 $O(n \log n)$ | 트리 구축 $O(n \log n)$ | 해시 테이블 구축 $O(n)$ |
| 정렬된 데이터 | 불필요 | 필요 | 필요 | 불필요 |

선택은 데이터 크기, 질의 지연 요구, 질의 횟수, 삽입·삭제 빈도, 정렬 유지 필요, 메모리 제한에도 달려 있습니다.

표의 수치는 사용 조건을 함께 읽어야 합니다. 이진 탐색의 로그 시간은 정렬된 배열과 임의 접근을 전제로 하며, 트리의 로그 시간은 균형이 유지된다는 전제를 갖습니다. 해시 조회의 상수 시간은 평균값으로, 적절한 해시 함수와 낮은 충돌률이 필요합니다. 조건이 깨지면 실제 성능과 최악의 복잡도는 표보다 나빠질 수 있습니다.

**선형 탐색**

- 매우 일반적이고 전처리가 필요 없습니다. 질의가 한 번뿐이면 정렬이나 보조 구조 구축 비용이 한 번의 순회보다 클 수 있습니다.
- 데이터가 작아 복잡도 차이가 실제 성능에 큰 영향을 주지 않을 때 적합합니다.
- 변경 뒤 보조 인덱스를 유지할 필요가 없어 갱신이 매우 잦은 데이터에 적합합니다.

**이진 탐색**

- 이미 정렬된 큰 데이터에 적합하고 최악의 경우에도 $O(\log n)$으로 안정적입니다.
- 크기가 배열에 필요한 연속 메모리를 할당할 수 있는 범위를 넘지 않아야 합니다.
- 정렬을 유지하려면 많은 원소를 이동해야 하므로 삽입과 삭제가 잦을 때는 적합하지 않습니다.
- 정적 배열을 여러 번 조회하거나 단조성이 있어 답 영역을 탐색할 수 있는 문제에 매우 유용합니다.

**해시 조회**

- 매우 빠른 키 질의가 필요할 때 적합하며 평균 복잡도는 $O(1)$입니다.
- 해시 테이블은 키를 정렬해 두지 않으므로 순서 유지나 범위 질의가 필요하면 적합하지 않습니다.
- 해시 함수, 적재율, 충돌 처리에 크게 의존하며 설계가 나쁘면 성능이 저하됩니다.
- 충돌을 줄이기 위해 충분한 버킷 공간이 필요하므로 메모리가 매우 제한되면 적합하지 않습니다.

**트리 탐색**

- 노드가 메모리에 흩어져 있어도 되므로 큰 데이터에 적합합니다.
- 순서를 유지하며 범위, 가장 가까운 원소, 최솟값과 최댓값 질의를 지원합니다.
- 일반 이진 탐색 트리는 삽입과 삭제가 반복되면 편향되어 시간이 $O(n)$까지 나빠질 수 있습니다.
- AVL이나 레드-블랙 트리는 모든 연산을 $O(\log n)$으로 유지하지만 회전과 균형 정보 갱신 비용이 추가됩니다.

모든 상황에 가장 좋은 방법은 없습니다. 한 번의 탐색 시간만 비교하지 말고 구축 비용, 예상 질의 수, 갱신 뒤 데이터 유지 비용까지 고려해야 합니다.

실무에서는 먼저 데이터가 이미 정렬되어 있는지, 순서나 범위 질의가 필요한지, 키 조회가 몇 번 반복되는지 확인하는 것이 좋습니다. 그다음 메모리 예산과 갱신 빈도를 더해 전체 비용을 비교합니다. 예를 들어 한 번만 읽을 작은 목록은 선형 탐색이 단순하고 빠르지만, 동일한 키 집합을 수백만 번 조회한다면 해시 테이블 구축 비용은 빠르게 회수됩니다. 정렬과 동적 갱신을 모두 지원해야 한다면 균형 트리가 더 자연스러운 선택입니다.
