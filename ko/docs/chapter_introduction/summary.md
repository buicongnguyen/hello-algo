# 요약

### 핵심 복습

- 알고리즘은 일상 어디에나 있으며 멀고 난해한 지식이 아닙니다. 우리는 자신도 모르는 사이 이미 많은 알고리즘을 익혔고 크고 작은 생활 문제를 해결하는 데 사용하고 있습니다.
- 사전에서 단어를 찾는 원리는 이진 탐색과 같습니다. 이진 탐색에는 문제를 나누어 해결하는 중요한 알고리즘 사고가 담겨 있습니다.
- 카드를 정리하는 과정은 삽입 정렬과 매우 비슷합니다. 삽입 정렬은 작은 데이터 집합을 정렬하는 데 적합합니다.
- 거스름돈을 계산하는 단계는 현재 상황에서 매번 가장 좋은 선택을 하는 그리디 알고리즘의 한 예입니다.
- 알고리즘은 유한한 시간 안에 특정 문제를 해결하는 명령 또는 작업 단계의 집합이고, 자료구조는 컴퓨터에서 데이터를 조직하고 저장하는 방식입니다.
- 자료구조와 알고리즘은 긴밀하게 연결됩니다. 자료구조는 알고리즘의 기반이며 알고리즘은 자료구조에 생명력을 불어넣습니다.
- 둘의 관계를 블록 조립에 비유할 수 있습니다. 블록은 데이터, 블록의 모양과 연결 방식은 자료구조, 블록을 조립하는 단계는 알고리즘에 해당합니다.

### 질문과 답변

**질문**: 프로그래머로 일하면서 알고리즘으로 문제를 해결한 적이 없습니다. 흔한 알고리즘은 이미 프로그래밍 언어에 구현되어 바로 쓸 수 있는데, 업무 문제가 아직 알고리즘이 필요한 수준에 이르지 않았다는 뜻인가요?

구체적인 업무 기술을 무술의 “기술”에 비유한다면, 기초 과목은 몸 안에 쌓는 “내공”에 더 가깝습니다.

알고리즘과 다른 기초 과목을 배우는 의미는 업무에서 모든 알고리즘을 처음부터 직접 구현하는 데 있지 않습니다. 배운 지식을 바탕으로 문제를 해결할 때 타당한 전문적 판단을 내리고, 결과적으로 작업 전체의 품질을 높이는 데 있습니다. 내장 정렬 함수를 예로 들어 봅시다.

라이브러리 함수가 이미 존재하더라도 입력의 성질과 함수의 비용을 이해해야 올바른 도구를 선택할 수 있습니다. 작은 데이터에서는 단순한 구현이 더 읽기 쉽고 충분히 빠를 수 있지만, 데이터가 커지거나 지연 시간과 메모리 제한이 엄격해지면 알고리즘 선택이 시스템 비용과 사용자 경험을 직접 바꿉니다. 기초 지식은 이런 경계를 알아보고 측정할 항목을 결정하는 판단 기준이 됩니다.

- 자료구조와 알고리즘을 공부하지 않았다면 주어진 데이터를 모두 내장 정렬 함수에 넘길 수 있습니다. 대부분 잘 동작하고 성능도 괜찮아 보여 문제가 없는 것처럼 느껴집니다.
- 알고리즘을 공부했다면 내장 정렬 함수의 시간 복잡도가 $O(n \log n)$임을 압니다. 하지만 데이터가 학생 번호처럼 자릿수가 고정된 정수라면 더 효율적인 “기수 정렬”을 사용해 시간 복잡도를 $O(nk)$로 줄일 수 있습니다. 여기서 $k$는 자릿수입니다. 데이터가 매우 많을 때 절약한 실행 시간은 비용 감소와 사용자 경험 개선이라는 실질적인 가치를 만듭니다.

이 예의 요점은 언제나 직접 정렬을 다시 구현하라는 뜻이 아닙니다. 데이터의 범위, 안정성 요구, 메모리 사용량과 구현 복잡도를 함께 비교한 뒤 내장 정렬이 적절한지 또는 특화된 방법이 실제 이점을 주는지 판단해야 한다는 뜻입니다. 알고리즘 지식은 성능 문제가 생긴 뒤 무작정 코드를 바꾸는 대신, 가설을 세우고 올바른 대안을 평가하게 해 줍니다.

공학 문제 중에는 최적의 해법을 찾기 어려운 것이 많고, 충분히 괜찮은 수준에서 해결되는 것도 많습니다. 문제의 난도는 한편으로 문제 자체의 성격에 달려 있고, 다른 한편으로 문제를 바라보는 사람의 지식에 달려 있습니다. 지식 체계가 완전하고 경험이 풍부할수록 더 깊이 분석하고 더 우아하게 문제를 해결할 수 있습니다.

자료구조와 알고리즘을 공부하는 일은 이러한 지식 체계의 공통 기반을 넓히는 과정입니다. 당장 특정 알고리즘을 구현하지 않더라도 성능의 병목, 자료 표현의 한계, 정확성과 자원 사용 사이의 절충을 더 일찍 발견할 수 있습니다. 그 결과 문제를 더 명확하게 설명하고 팀과 더 나은 설계 결정을 내릴 수 있습니다.
