# 알고리즘이란 무엇인가

## 알고리즘의 정의

<u>알고리즘</u>은 유한한 시간 안에 특정 문제를 해결하는 명령 또는 연산 단계의 집합입니다. 알고리즘에는 다음과 같은 특징이 있습니다.

- 문제가 명확하게 정의되어 있고 입력과 출력도 분명합니다.
- 실제로 수행할 수 있으며 유한한 단계, 시간, 메모리 안에서 완료됩니다.
- 각 단계의 의미가 확정적이며, 같은 입력과 실행 조건에서는 항상 같은 출력이 나옵니다.

이 세 조건은 단순한 요리법과 컴퓨터 프로그램을 모두 알고리즘의 관점에서 살펴보게 해 줍니다. 입력이 무엇인지, 원하는 출력이 무엇인지, 각 단계가 실제로 수행 가능한지, 언젠가 종료하는지를 확인하면 절차가 문제를 제대로 해결하는지 판단할 수 있습니다. 반대로 단계가 모호하거나 끝나지 않는 절차는 실행 가능한 알고리즘으로 보기 어렵습니다.

## 자료구조의 정의

<u>자료구조</u>는 데이터를 조직하고 저장하는 방식으로, 데이터 자체와 데이터 요소 사이의 관계, 그리고 데이터를 다루는 연산 방법을 포함합니다. 자료구조는 다음 목표를 고려해 설계합니다.

- 가능한 한 적은 공간을 차지하여 컴퓨터 메모리를 절약합니다.
- 데이터 접근, 추가, 삭제, 갱신 등의 연산을 가능한 한 빠르게 수행합니다.
- 알고리즘이 효율적으로 실행될 수 있도록 간결한 데이터 표현과 논리 정보를 제공합니다.

**자료구조 설계는 여러 조건 사이에서 균형을 선택하는 과정입니다**. 한 측면을 개선하려면 다른 측면에서 어느 정도 양보해야 할 때가 많습니다. 두 가지 예를 살펴봅시다.

- 연결 리스트는 배열보다 데이터를 추가하고 삭제하기 편하지만 데이터 접근 속도를 희생합니다.
- 그래프는 연결 리스트보다 풍부한 논리 관계를 표현하지만 더 많은 메모리 공간이 필요합니다.

따라서 “가장 좋은 자료구조”는 문제와 무관하게 하나로 정해지지 않습니다. 어떤 연산이 자주 일어나는지, 데이터가 얼마나 커지는지, 저장 공간에 어떤 제한이 있는지를 먼저 알아야 합니다. 빠른 접근이 중요하면 연속 저장이 유리할 수 있고, 관계 표현이나 유연한 추가가 중요하면 포인터와 연결 정보를 위해 더 많은 공간을 사용할 수 있습니다.

## 자료구조와 알고리즘의 관계

아래 그림처럼 자료구조와 알고리즘은 서로 깊이 관련되어 있으며 긴밀하게 결합되어 있습니다. 구체적으로 다음 세 가지 관계가 있습니다.

- 자료구조는 알고리즘의 기반입니다. 알고리즘이 사용할 데이터를 구조적으로 저장하고 그 데이터를 다루는 방법을 제공합니다.
- 알고리즘은 자료구조에 생명력을 불어넣습니다. 자료구조 자체는 데이터 정보만 저장하지만 알고리즘과 결합하면 구체적인 문제를 해결할 수 있습니다.
- 하나의 알고리즘도 여러 자료구조를 바탕으로 구현할 수 있지만 실행 효율은 크게 달라질 수 있습니다. 알맞은 자료구조를 선택하는 일이 중요합니다.

같은 목표를 가진 알고리즘도 입력을 배열에 저장하는지, 연결 구조나 해시 테이블에 저장하는지에 따라 필요한 단계가 달라집니다. 반대로 같은 자료구조도 순회, 탐색, 정렬과 같은 서로 다른 알고리즘과 결합하여 여러 문제를 해결합니다. 두 요소를 따로 암기하기보다 “어떤 데이터를 어떤 형태로 저장하고, 그 위에서 어떤 절차를 수행하는가”라는 하나의 설계로 이해하는 편이 좋습니다.

![블록 조립](what_is_dsa.assets/assembling_blocks.png)

표: 자료구조와 알고리즘을 블록 조립에 비유

| 자료구조와 알고리즘 | 블록 조립 |
| ------------------- | --------- |
| 입력 데이터 | 조립하지 않은 블록 |
| 자료구조 | 블록의 모양, 크기, 연결 방법 등을 포함한 조직 방식 |
| 알고리즘 | 블록을 목표 모형으로 조립하는 일련의 작업 단계 |
| 출력 데이터 | 완성된 블록 모형 |

자료구조와 알고리즘은 특정 프로그래밍 언어에 종속되지 않습니다. 이것이 이 책에서 여러 프로그래밍 언어의 구현을 함께 제공할 수 있는 이유입니다.
