# 요약

### 핵심 복습

- 동적 계획법은 문제를 하위 문제로 분해하고 그 해를 저장하여 반복 계산을 피하므로 실행 효율을 크게 높입니다.
- 시간 제한을 무시하면 모든 동적 계획법 문제를 백트래킹, 즉 완전 탐색으로 풀 수 있습니다. 그러나 재귀 트리에 겹치는 하위 문제가 매우 많아 효율이 낮습니다. 메모 배열은 계산한 결과를 저장해 각 하위 문제를 한 번만 계산하게 합니다.
- 메모이제이션은 하향식 재귀 해법이고, 이에 대응하는 동적 계획법은 “표 채우기”와 같은 상향식 반복 해법입니다. 현재 상태가 소수의 가까운 상태에만 의존한다면 $dp$ 테이블의 한 차원을 없애 메모리를 줄일 수 있습니다.
- 문제 분해는 널리 쓰이는 알고리즘 사고이지만 분할 정복, 동적 계획법, 백트래킹에서는 서로 다른 성질을 가집니다.
- 동적 계획법 문제의 세 가지 주요 특징은 겹치는 하위 문제, 최적 부분 구조, 무후효성입니다.
- 원문제의 최적해를 하위 문제의 최적해로 만들 수 있다면 최적 부분 구조를 가집니다.
- 무후효성은 현재 상태를 알고 있을 때 미래의 전개가 그 상태에만 관련되고 전체 과거에는 의존하지 않는 성질입니다. 많은 조합 최적화 문제는 이 성질을 만족하지 않아 동적 계획법으로 효율적으로 풀기 어렵습니다.

동적 계획법 문제를 풀 때에는 먼저 한 차례의 선택을 말로 설명하고, 그 선택 이후 남는 문제를 완전히 표현하는 최소 상태를 찾습니다. 상태의 각 변수는 `dp` 테이블의 한 차원이 되므로 변수의 범위가 전체 시간과 공간 복잡도를 결정합니다. 그다음 현재 상태로 들어오는 모든 합법적인 이전 상태를 열거하고, 최솟값·최댓값·경우의 수 같은 문제 목표에 맞춰 결합합니다. 마지막으로 경계 상태를 초기화하고, 각 상태를 계산할 때 필요한 이전 값이 이미 준비되는 순회 방향을 선택해야 합니다.

완전 탐색에서 동적 계획법으로 발전시키는 과정은 정확성을 검증하는 좋은 방법입니다. 완전 탐색은 선택, 종료 조건, 불가능한 상태를 드러내고, 메모이제이션은 동일한 상태의 반복을 제거합니다. 같은 점화식을 상향식 표 채우기로 옮길 때에는 재귀 호출의 의존 순서를 반복문의 순서로 바꿉니다. 결과가 다르다면 대개 상태 정의, 경계 초기화, 순회 순서 가운데 하나가 잘못된 것입니다.

**배낭 문제**

- 배낭 문제는 가장 대표적인 동적 계획법 문제이며 0-1 배낭, 완전 배낭, 다중 배낭 같은 변형이 있습니다.
- 0-1 배낭의 상태는 앞의 $i$개 물건과 용량 $c$로 얻는 최대 가치입니다. 현재 물건을 선택하지 않거나 선택하는 두 결정에서 최적 부분 구조와 상태 전이 방정식을 얻습니다. 공간 최적화 뒤에는 위쪽과 왼쪽 위 상태를 보존해야 하므로 배열을 역방향으로 순회합니다.
- 완전 배낭은 각 종류를 선택하는 횟수에 제한이 없으므로 선택할 때의 전이가 0-1 배낭과 다릅니다. 현재 상태가 위쪽과 왼쪽 상태에 의존하므로 공간 최적화 뒤에는 정방향으로 순회합니다.
- 동전 교환은 완전 배낭의 변형입니다. 목표가 “최대 가치”에서 “최소 동전 수”로 바뀌므로 상태 전이의 $\max()$가 $\min()$으로 바뀝니다. “용량을 넘지 않기”가 아니라 “목표 금액을 정확히 만들기”를 요구하므로 $amt + 1$로 유효하지 않은 해를 나타냅니다.
- 동전 교환 II는 목표가 “최소 동전 수”에서 “조합 수”로 바뀌므로 상태 전이의 $\min()$ 대신 덧셈을 사용합니다.

0-1 배낭과 완전 배낭의 일차원 최적화에서 순회 방향은 단순한 구현 취향이 아닙니다. 역방향 순회는 현재 물건을 처리하기 전 행의 값을 읽어 같은 물건의 중복 선택을 막고, 정방향 순회는 현재 행에서 방금 갱신한 값을 다시 사용해 같은 종류를 여러 번 선택하게 합니다. 문제의 선택 횟수 제약과 배열 갱신 방향이 정확히 대응해야 합니다.

동전 교환에서도 초기값은 답의 의미를 반영해야 합니다. 최소 개수를 구할 때 만들 수 없는 금액은 매우 큰 값으로 두어 최솟값 후보에서 제외하고, 조합 수를 셀 때 금액 0은 아무 동전도 고르지 않는 한 가지 방법으로 둡니다. 같은 상태 공간이라도 최적화 연산과 항등원, 불가능한 상태의 표현이 달라지면 초기화도 함께 달라집니다.

**편집 거리 문제**

- 편집 거리, 즉 레벤슈타인 거리는 두 문자열의 유사도를 측정하며 한 문자열을 다른 문자열로 바꾸는 데 필요한 최소 편집 횟수입니다. 가능한 연산은 삽입, 삭제, 교체입니다.
- 상태는 $s$의 앞 $i$개 문자를 $t$의 앞 $j$개 문자로 바꾸는 최소 단계 수입니다. $s[i-1] \ne t[j-1]$이면 삽입, 삭제, 교체의 세 결정이 각각 하위 문제로 이어지고, $s[i-1] = t[j-1]$이면 현재 문자를 편집하지 않습니다.
- 편집 거리의 상태는 위쪽, 왼쪽, 왼쪽 위 칸에 의존합니다. 공간 최적화 뒤에는 정방향과 역방향 어느 쪽도 필요한 모든 값을 저절로 보존하지 못합니다. 따라서 임시 변수 하나로 왼쪽 위 상태를 저장하면 완전 배낭과 비슷한 상황이 되어 정방향 순회가 가능합니다.

편집 거리의 세 전이는 각각 삽입, 삭제, 교체라는 실제 연산에 대응합니다. 마지막 문자가 같을 때에는 비용을 더하지 않고 왼쪽 위 상태를 그대로 이어 받습니다. 이 의미를 기억하면 공식을 암기하지 않아도 표의 어느 이웃을 참조해야 하는지 다시 유도할 수 있습니다. 첫 번째 행과 첫 번째 열은 빈 문자열과의 변환 비용이므로 인덱스 자체로 초기화합니다.

공간 최적화는 올바른 이차원 풀이를 완성하고 검증한 뒤 적용하는 편이 안전합니다. 메모리를 줄이면 덮어쓰기 전의 값과 갱신 뒤의 값이 같은 배열에 섞이므로, 각 변수가 어느 시점의 상태를 나타내는지 명확히 해야 합니다. 입력 크기가 충분히 작다면 더 읽기 쉬운 전체 표가 디버깅과 경로 복원에 유리할 수도 있습니다. 최적화는 항상 문제의 제약과 필요한 출력에 맞춰 선택합니다.
