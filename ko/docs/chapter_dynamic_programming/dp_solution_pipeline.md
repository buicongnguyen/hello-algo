# 동적 계획법 문제 해결 절차

앞의 두 절에서 동적 계획법 문제의 주요 특징을 살펴보았습니다. 이제 더 실용적인 두 질문에 답해 봅시다.

1. 어떤 문제가 동적 계획법에 적합한지 어떻게 알아볼 수 있을까요?
2. 동적 계획법 문제를 푸는 전체 절차는 무엇이며 어디에서 시작해야 할까요?

## 문제 식별

일반적으로 겹치는 하위 문제, 최적 부분 구조, 무후효성을 가진 문제는 동적 계획법에 적합합니다. 그러나 문제 설명에서 이 세 특징을 곧바로 찾아내기는 어렵습니다. 그래서 조건을 조금 느슨하게 보고, **먼저 문제가 백트래킹, 즉 완전 탐색으로 표현될 수 있는지 살펴봅니다**.

**백트래킹에 적합한 문제는 대개 “의사 결정 트리 모형”을 만족합니다.** 문제를 트리로 표현할 수 있고, 각 노드는 한 번의 결정이며 각 경로는 결정의 연속입니다.

다시 말해 문제에 분명한 선택의 개념이 있고 일련의 결정으로 해를 만들 수 있다면 의사 결정 트리 모형을 만족하며, 보통 백트래킹으로 풀 수 있습니다.

그 가운데 동적 계획법 문제에는 다음과 같은 긍정적 신호가 더 나타납니다.

- 문제에 최댓값, 최솟값, 가장 많음, 가장 적음과 같은 표현이 있어 최적화 목표를 드러냅니다.
- 상태를 리스트, 다차원 행렬, 트리 등으로 나타낼 수 있고 한 상태와 이웃 상태 사이에 재귀 관계가 있습니다.

반대로 다음은 부정적 신호입니다.

- 최적해 하나가 아니라 가능한 모든 구체적 해를 찾아야 합니다.
- 순열이나 조합의 성격이 뚜렷하고 여러 해 자체를 반환해야 합니다.

문제가 의사 결정 트리 모형을 만족하고 긍정적 신호가 비교적 분명하다면 우선 동적 계획법 문제라고 가정하고, 풀이를 전개하면서 그 가정을 검증할 수 있습니다.

## 해결 단계

문제의 성격과 난이도에 따라 세부 절차는 달라지지만 보통 결정 기술, 상태 정의, $dp$ 테이블 설정, 상태 전이 방정식 유도, 경계 조건 결정, 상태 전이 순서 결정의 단계로 진행합니다.

이 전체 과정에서 $dp$ 테이블은 각 상태와 그에 대응하는 하위 문제의 해를 연결하는 구조화된 기록입니다.

좋은 상태 정의는 너무 적은 정보도 너무 많은 정보도 담지 않습니다. 정보가 부족하면 서로 다른 미래를 가진 경로가 같은 상태로 섞여 잘못된 전이가 생기고, 정보가 지나치게 많으면 상태 수가 불필요하게 커집니다. 결정 변수를 하나씩 적고, 현재 상태만으로 다음 선택과 최종 목표를 계산할 수 있는지 확인하는 과정이 출발점입니다.

고전적인 “최소 경로 합” 문제로 절차를 구체적으로 살펴봅시다.

!!! question

    각 칸에 음이 아닌 정수 비용이 들어 있는 $n \times m$ 이차원 격자 `grid`가 있습니다. 로봇은 왼쪽 위 칸에서 시작해 한 번에 아래쪽이나 오른쪽으로만 이동하여 오른쪽 아래 칸까지 갑니다. 시작점에서 끝점까지 경로의 최소 비용 합을 반환하세요.

아래 예에서 격자의 최소 경로 합은 $13$입니다.

![최소 경로 합 예제](dp_solution_pipeline.assets/min_path_sum_example.png)

**1단계: 각 차례의 결정을 살펴보고 상태를 정의한 뒤 $dp$ 테이블을 만듭니다**

매 차례 로봇은 한 칸 아래 또는 오른쪽으로 이동합니다. 현재 행과 열 인덱스를 $[i, j]$라고 하면 이동 뒤에는 $[i+1, j]$ 또는 $[i, j+1]$이 됩니다. 따라서 상태에는 행과 열 두 변수가 필요하며 $[i, j]$로 표시합니다.

상태 $[i, j]$는 **시작점 $[0, 0]$에서 $[i, j]$까지의 최소 경로 합**이라는 하위 문제에 대응하며, 그 해를 $dp[i, j]$로 표시합니다.

그러면 아래 그림처럼 입력 격자 $grid$와 같은 크기의 이차원 $dp$ 행렬을 얻습니다.

![상태 정의와 dp 테이블](dp_solution_pipeline.assets/min_path_sum_solution_state_definition.png)

!!! note

    동적 계획법과 백트래킹은 모두 일련의 결정으로 설명할 수 있습니다. 상태는 모든 결정 변수를 포함해야 하며, 문제 해결의 진행 정도를 완전히 나타내고 다음 상태를 유도할 수 있을 만큼 충분한 정보를 가져야 합니다.

    각 상태는 하나의 하위 문제에 대응합니다. $dp$ 테이블은 모든 하위 문제의 해를 저장하고, 상태의 독립 변수 하나가 테이블의 한 차원을 이룹니다. 본질적으로 $dp$ 테이블은 상태에서 하위 문제의 해로 가는 사상입니다.

**2단계: 최적 부분 구조를 찾고 상태 전이 방정식을 유도합니다**

상태 $[i, j]$에는 위쪽 칸 $[i-1, j]$ 또는 왼쪽 칸 $[i, j-1]$에서만 들어올 수 있습니다. 따라서 최적 부분 구조는 다음과 같습니다. $[i, j]$까지의 최소 경로 합은 $[i, j-1]$까지의 최소 경로 합과 $[i-1, j]$까지의 최소 경로 합 중 더 작은 값으로 결정됩니다.

이 분석으로 상태 전이 방정식을 얻습니다.

$$
dp[i, j] = \min(dp[i-1, j], dp[i, j-1]) + grid[i, j]
$$

![최적 부분 구조와 상태 전이 방정식](dp_solution_pipeline.assets/min_path_sum_solution_state_transition.png)

!!! note

    정의한 $dp$ 테이블을 바탕으로 원문제와 하위 문제의 관계를 살펴보고, 하위 문제의 최적해로 원문제의 최적해를 만드는 방법을 찾습니다. 이것이 최적 부분 구조입니다.

    최적 부분 구조를 찾은 뒤에는 그 관계를 상태 전이 방정식으로 표현합니다.

**3단계: 경계 조건과 상태 전이 순서를 결정합니다**

첫 번째 행의 상태에는 왼쪽 칸에서만 들어올 수 있고, 첫 번째 열의 상태에는 위쪽 칸에서만 들어올 수 있습니다. 따라서 첫 번째 행 $i = 0$과 첫 번째 열 $j = 0$이 경계 조건입니다.

아래 그림처럼 각 칸이 왼쪽과 위쪽 칸에 의존하므로 바깥 반복문은 행, 안쪽 반복문은 열 순서로 행렬을 순회합니다.

![경계 조건과 상태 전이 순서](dp_solution_pipeline.assets/min_path_sum_solution_initial_state.png)

!!! note

    동적 계획법에서 경계 조건은 $dp$ 테이블을 초기화하는 데 쓰이고, 탐색에서는 가지치기 조건으로 쓰입니다.

    상태 전이 순서는 현재 하위 문제를 계산할 때 의존하는 모든 더 작은 하위 문제가 이미 올바르게 계산되어 있음을 보장해야 합니다.

이 분석만으로 동적 계획법 코드를 바로 작성할 수 있습니다. 다만 문제 분해는 하향식 사고이므로 “완전 탐색 $\rightarrow$ 메모이제이션 $\rightarrow$ 동적 계획법” 순서로 발전시키는 편이 자연스럽습니다.

이 발전 순서는 단순한 구현 연습이 아니라 점화식의 정확성을 확인하는 도구입니다. 완전 탐색은 각 선택의 의미와 종료 조건을 드러내고, 메모이제이션은 실제로 같은 상태가 반복되는지 보여 주며, 상향식 변환은 의존 관계에 맞는 계산 순서를 요구합니다. 어느 단계에서 상태가 부족하거나 경계가 잘못되면 작은 예제로 즉시 추적하여 수정할 수 있습니다.

### 방법 1: 완전 탐색

상태 $[i, j]$에서 시작해 더 작은 상태 $[i-1, j]$와 $[i, j-1]$로 계속 분해합니다. 재귀 함수의 구성 요소는 다음과 같습니다.

- **재귀 매개변수**: 상태 $[i, j]$.
- **반환값**: $[0, 0]$에서 $[i, j]$까지의 최소 경로 합, 즉 $dp[i, j]$.
- **종료 조건**: $i = 0$이고 $j = 0$이면 비용 $grid[0, 0]$을 반환합니다.
- **가지치기**: $i < 0$ 또는 $j < 0$이면 격자 밖이므로 불가능한 상태를 나타내는 비용 $+\infty$를 반환합니다.

공식 구현은 다음 위치에 삽입됩니다.

```python
# 잠긴 원문의 13개 언어 최소 경로 합 DFS 공식 코드가 이 위치에 삽입됩니다.
```

아래 그림은 $dp[2, 1]$을 루트로 하는 재귀 트리입니다. 트리에는 겹치는 하위 문제가 많으며 `grid`의 크기가 커질수록 그 수가 빠르게 증가합니다.

겹치는 하위 문제가 생기는 근본 원인은 **왼쪽 위에서 같은 칸까지 오는 서로 다른 경로가 여러 개 존재하기 때문**입니다.

![완전 탐색의 재귀 트리](dp_solution_pipeline.assets/min_path_sum_dfs.png)

각 상태에는 아래쪽과 오른쪽 두 선택이 있습니다. 왼쪽 위에서 오른쪽 아래까지 이동 횟수는 $m + n - 2$이므로 최악의 시간 복잡도는 $O(2^{m + n})$입니다. 여기서 $n$과 $m$은 각각 행과 열의 수입니다. 이 추정은 격자 경계 근처에서 선택이 하나로 줄어드는 사실을 반영하지 않으므로 실제 경로 수는 조금 적습니다.

더 정확한 경로 수는 아래쪽 이동과 오른쪽 이동을 배열하는 조합으로 셀 수 있지만, 완전 탐색이 입력 크기에 따라 매우 빠르게 커진다는 결론은 같습니다. 복잡도 분석의 목적은 정확한 상수보다 계산이 어떤 크기 함수로 증가하는지 파악하고, 저장을 통해 어떤 반복을 제거할 수 있는지 찾는 데 있습니다.

### 공간 최적화

각 칸은 왼쪽 칸과 위쪽 칸에만 의존하므로 한 행짜리 배열로 $dp$ 테이블을 표현할 수 있습니다.

이때 배열 `dp`는 한 행의 상태만 나타냅니다. 따라서 첫 번째 열의 모든 상태를 미리 초기화할 수 없고, 각 행을 순회할 때 첫 번째 열을 갱신해야 합니다.

```python
# 잠긴 원문의 13개 언어 공간 최적화 최소 경로 합 공식 코드가 이 위치에 삽입됩니다.
```
