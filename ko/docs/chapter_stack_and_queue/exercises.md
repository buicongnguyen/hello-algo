# 연습문제

## 개념 복습

### 스택과 큐에서 어떤 원소가 먼저 나갈까?

빈 스택 `S`와 빈 큐 `Q`를 준비하고 각 구조에 다음과 같은 연산을 수행합니다.

1. `A`를 추가합니다.
2. `B`를 추가합니다.
3. 원소 하나를 제거하여 기록합니다.
4. `C`를 추가합니다.
5. 구조가 빌 때까지 원소를 계속 제거하여 기록합니다.

`S`와 `Q`에서 원소가 나오는 순서를 각각 쓰고, 후입선출과 선입선출 원칙으로 차이를 설명하세요.

??? success "정답"

    스택 `S`에서 나오는 순서는 `B, C, A`입니다. `A`와 `B`를 넣은 뒤에는 가장 최근에 들어온 `B`가 먼저 나옵니다. 이어서 `C`를 넣으면 `C`, `A` 순서로 나옵니다. 이것이 후입선출입니다.

    큐 `Q`에서 나오는 순서는 `A, B, C`입니다. `A`와 `B`를 넣은 뒤에는 먼저 도착한 `A`가 먼저 나옵니다. `C`를 넣은 뒤에도 남은 도착 순서에 따라 `B`, `C`가 나옵니다. 이것이 선입선출입니다.

두 구조에 같은 입력과 연산을 적용해도 제거 순서가 달라지는 이유는 저장 장치가 아니라 외부에 허용된 끝 위치가 다르기 때문입니다.

### 큐의 뒤가 배열 끝을 넘어가면 어떻게 될까?

길이가 5이고 인덱스가 `0–4`인 원형 배열 큐가 있습니다. 현재 `front = 3`, `size = 2`이며 원소 `A`, `B`가 각각 인덱스 3과 4에 놓여 있습니다.

<!-- numbered-subquestions -->

1. `C`를 인큐하면 어느 인덱스에 저장해야 하며 새 `size`는 얼마입니까?
2. 이어서 한 번 디큐하면 어떤 원소가 제거되고 새 `front`와 `size`는 얼마입니까?
3. 현재 앞에서 뒤까지의 논리적 원소 순서는 무엇입니까? 디큐할 때 다른 배열 원소를 이동해야 합니까? 이유를 설명하세요.

??? success "정답"

    1. 새 원소의 위치는 `(front + size) % 5 = (3 + 2) % 5 = 0`이므로 `C`는 인덱스 0에 저장됩니다. 인큐 뒤에는 `size = 3`입니다.

    2. 디큐는 현재 앞 원소 `A`를 제거합니다. 새 앞 인덱스는 `(3 + 1) % 5 = 4`이므로 `front = 4`, `size = 2`입니다.

    3. 유효한 원소의 논리 순서는 `B, C`입니다. `B`는 인덱스 4, `C`는 인덱스 0에 있습니다. 디큐는 `front`와 `size`만 바꾸며 원형 배열이 나머지 연산으로 인덱스를 처음으로 순환시키므로 다른 원소를 이동할 필요가 없습니다.

이 예제는 물리 인덱스의 오름차순과 큐의 논리 순서가 항상 같지 않다는 점을 보여 줍니다.

### 덱의 양쪽 끝 연산

여기서 `push_first`는 앞에 추가하고, `push_last`는 뒤에 추가하며, `pop_first`는 앞에서 제거하고, `pop_last`는 뒤에서 제거합니다.

빈 덱 `deq`에 다음 연산을 수행하세요.

1. `push_last(A)`
2. `push_last(B)`
3. `push_first(C)`
4. `pop_last()`
5. `push_last(D)`
6. `pop_first()`

<!-- numbered-subquestions -->

1. 두 팝 연산은 각각 어떤 원소를 반환합니까?
2. 모든 연산 뒤에 앞에서 뒤 순서로 어떤 원소가 남습니까?
3. 뒤에만 추가하고 앞에서만 제거하는 큐가 여섯 연산을 모두 수행할 수 있습니까? 지원하지 않는 연산을 지적하고 덱이 가능한 이유를 설명하세요.

??? success "정답"

    처음 세 단계 뒤 덱의 앞에서 뒤 순서는 `[C, A, B]`입니다.

    <!-- numbered-subquestions -->

    1. `pop_last()`는 `B`를 제거합니다. `D`를 추가하면 `[C, A, D]`가 되고, 이어서 `pop_first()`는 `C`를 제거합니다.

    2. 남은 두 원소는 `[A, D]`입니다.

    3. 일반 큐는 모든 연산을 수행할 수 없습니다. 3단계 `push_first(C)`는 앞 추가를, 4단계 `pop_last()`는 뒤 제거를 요구합니다. 덱은 양쪽 끝에서 추가와 제거를 모두 허용하므로 여섯 단계를 수행할 수 있습니다.

각 단계에서 앞과 뒤 위치를 함께 기록하면 복잡한 덱 연산도 실수 없이 추적할 수 있습니다.

### 괄호 문자열 검사

문자열 `s`에는 세 종류의 괄호 `()`, `[]`, `{}`만 들어 있습니다. 스택을 사용하여 문자열이 올바른지 판정하세요.

올바른 문자열은 두 조건을 모두 만족해야 합니다. 각 닫는 괄호는 아직 짝을 찾지 못한 가장 최근의 여는 괄호와 같은 종류여야 하며, 전체 문자열을 처리한 뒤 짝이 없는 여는 괄호가 남으면 안 됩니다. 결과를 불리언 값으로 반환하세요.

빈 문자열을 어떻게 처리할지, 첫 문자가 닫는 괄호인 경우와 서로 다른 종류가 교차하는 경우도 확인하세요.

??? tip "힌트"

    1. 각 닫는 괄호를 대응하는 여는 괄호로 매핑합니다.
    2. 여는 괄호를 만나면 스택에 넣습니다.
    3. 닫는 괄호를 만나면 먼저 스택이 비었는지 확인하고, 꼭대기 원소가 대응하는 여는 괄호인지 검사한 뒤 팝합니다.
    4. 모든 문자를 처리한 뒤 스택도 비어 있어야 합니다.
