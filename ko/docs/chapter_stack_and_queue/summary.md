# 5장 요약

### 핵심 복습

- 스택은 후입선출 원칙을 따르며 배열이나 연결 리스트로 구현할 수 있습니다.
- 배열 기반 스택은 평균 실행 효율과 캐시 지역성이 높은 편이지만, 배열 확장이 일어나는 한 번의 푸시는 $O(n)$까지 느려질 수 있습니다. 연결 리스트 기반 구현은 용량 복사가 없어 개별 연산 비용이 더 안정적입니다.
- 공간 측면에서 동적 배열은 사용하지 않는 예약 용량을 남길 수 있고, 연결 리스트는 노드마다 추가 참조와 객체 관리 정보를 저장합니다. 어느 쪽이 항상 더 적은 메모리를 쓴다고 단정할 수 없습니다.
- 큐는 선입선출 원칙을 따르며 배열이나 연결 리스트로 구현할 수 있습니다. 원형 배열은 앞 원소를 실제로 이동하지 않고 인덱스를 순환시켜 빠른 인큐와 디큐를 제공합니다.
- 덱은 앞과 뒤 양쪽에서 원소를 추가하고 제거할 수 있는 더 유연한 큐입니다. 이중 연결 리스트 또는 원형 배열로 구현할 수 있습니다.

스택, 큐, 덱은 저장 방식보다 허용되는 연산과 처리 순서로 정의됩니다. 같은 배열이나 연결 리스트를 사용하더라도 인터페이스를 제한하면 서로 다른 추상 자료구조가 됩니다. 문제에서 가장 최근 항목을 먼저 처리하면 스택, 가장 먼저 도착한 항목을 먼저 처리하면 큐, 양쪽 끝 정책이 필요하면 덱을 우선 고려할 수 있습니다.

### 질문과 답변

**브라우저의 앞으로 가기와 뒤로 가기를 이중 연결 리스트로 구현하나요?**

브라우저 이동의 핵심 행동은 스택 응용으로 설명할 수 있습니다. 새 페이지를 방문하면 이전 상태를 뒤로 가기 스택에 넣고, 뒤로 가기를 누르면 가장 최근 상태를 꺼내 앞으로 가기 스택으로 옮깁니다. 실제 제품은 방문 기록 탐색, 탭 상태, 메모리 제한 같은 요구 때문에 더 복잡한 구조를 사용할 수 있지만 LIFO 원리는 두 스택으로 명확하게 표현됩니다.

**연결 리스트 스택에서 노드를 팝한 뒤 메모리를 해제해야 하나요?**

노드를 이후에도 사용한다면 즉시 해제하면 안 됩니다. 더 이상 사용하지 않을 때 Java와 Python 같은 언어는 도달할 수 없는 객체를 가비지 컬렉터가 회수합니다. C와 C++처럼 수동 메모리 관리가 필요한 언어에서는 소유권을 확인하고 직접 해제해야 하며, 다른 참조가 남아 있는 노드를 너무 일찍 해제하지 않도록 주의해야 합니다.

**덱은 두 스택을 붙인 것처럼 보이는데 어디에 사용하나요?**

덱은 스택과 큐의 논리를 모두 표현하며 양쪽 끝에 추가 규칙이 필요한 상황에서 유용합니다. 제한된 실행 취소 기록은 최신 변경을 한쪽에서 꺼내면서 오래된 기록을 반대쪽에서 버립니다. 슬라이딩 윈도 알고리즘은 후보를 양쪽에서 제거하고, 작업 스케줄러는 한쪽에서 처리하면서 반대쪽의 작업을 다른 실행자가 가져갈 수 있습니다.

**실행 취소와 다시 실행은 구체적으로 어떻게 구현하나요?**

실행 취소용 스택 `A`와 다시 실행용 스택 `B`를 사용합니다.

1. 사용자가 새 작업을 수행할 때 작업을 `A`에 넣고 `B`를 모두 비웁니다. 새로운 분기가 시작되었으므로 이전 다시 실행 기록은 더 이상 유효하지 않습니다.
2. 실행 취소 시 `A`의 가장 최근 작업을 꺼내 역연산을 수행하고 그 작업을 `B`에 넣습니다.
3. 다시 실행 시 `B`의 가장 최근 작업을 꺼내 다시 적용하고 `A`로 돌려놓습니다.

두 스택의 꼭대기가 현재 상태에서 가장 가까운 과거와 미래를 각각 나타내므로 여러 단계를 자연스럽게 왕복할 수 있습니다.
