# 큐

<u>큐</u>는 선입선출(First In, First Out, FIFO) 규칙을 따르는 선형 자료구조입니다. 이름처럼 사람들이 줄을 서서 기다리는 상황을 모델링합니다. 새로 온 사람은 줄의 뒤에 서고, 가장 먼저 도착해 앞에 있는 사람부터 차례로 나갑니다.

아래 그림에서 원소가 나가는 쪽을 **앞(front)**, 새 원소가 들어오는 쪽을 **뒤(rear)**라고 합니다. 뒤에 원소를 추가하는 연산을 **인큐(enqueue)**, 앞의 원소를 제거하는 연산을 **디큐(dequeue)**라고 합니다. 어느 시점에도 중간 원소를 먼저 꺼내지 않기 때문에 도착 순서가 처리 순서로 유지됩니다.

표: 큐 연산의 효율

| 메서드 | 설명 | 시간 복잡도 |
| --- | --- | --- |

## 큐 구현

큐를 구현하려면 한쪽 끝에서 원소를 추가하고 반대쪽 끝에서 제거할 수 있는 저장 구조가 필요합니다. 연결 리스트와 배열 모두 이 요구를 만족하지만, 효율적인 끝 위치를 선택하고 인덱스를 관리하는 방식이 서로 다릅니다.

### 연결 리스트 기반 구현

연결 리스트의 머리 노드와 꼬리 노드를 각각 큐의 앞과 뒤로 사용합니다. 새 노드는 꼬리 뒤에만 붙이고, 제거는 머리에서만 수행합니다. 머리와 꼬리 참조를 둘 다 유지하면 어느 연산도 리스트 전체를 순회할 필요가 없습니다.

### 배열 기반 구현

배열의 첫 원소를 실제로 삭제하면 뒤 원소를 모두 왼쪽으로 옮겨야 하므로 $O(n)$ 시간이 걸립니다. 그러나 앞 원소가 있는 인덱스를 별도 변수로 기록하면 이동을 피할 수 있습니다.

`front`는 첫 유효 원소의 인덱스, `size`는 현재 큐 길이를 나타냅니다. `rear = front + size`로 정의하면 `rear`는 마지막 원소 바로 다음의 삽입 위치입니다. 따라서 유효한 원소의 논리 범위는 `[front, rear - 1]`입니다.

- 인큐: 인덱스 `rear`에 새 원소를 기록하고 `size`를 1 늘립니다.
- 디큐: 값을 이동하지 않고 `front`를 1 늘린 뒤 `size`를 1 줄입니다.

각 연산은 일정한 수의 인덱스와 크기 갱신만 수행하므로 $O(1)$ 시간에 끝납니다.

![배열 기반 큐의 인큐와 디큐](queue.assets/array_queue_step1.png)

![배열 큐의 뒤에 원소 추가](queue.assets/array_queue_step2_push.png)

![배열 큐의 앞에서 원소 제거](queue.assets/array_queue_step3_pop.png)

계속 인큐와 디큐를 반복하면 `front`와 `rear`가 오른쪽으로 이동해 배열 끝에 도달합니다. 앞쪽에는 이미 사용을 마친 빈칸이 있어도 단순한 직선 인덱스로는 다시 사용할 수 없습니다. 이 문제는 배열의 끝과 시작이 연결된 것처럼 취급하는 **원형 배열**로 해결합니다.

인덱스가 배열 길이를 넘어가면 나머지 연산으로 처음 위치로 되돌립니다. 논리적으로 다음 위치로 한 칸 이동하지만 물리 인덱스는 끝에서 0으로 순환합니다.

이 학습용 큐는 고정 용량이라는 한계가 있습니다. 동적 배열과 확장 메커니즘을 결합하면 더 많은 원소를 받을 수 있지만, 확장할 때에는 논리적 앞에서 뒤 순서로 새 배열에 복사해 순환된 배치를 다시 정리해야 합니다.

두 구현의 비교는 스택과 비슷합니다. 배열은 연속 메모리와 좋은 캐시 지역성을 얻지만 용량과 순환 인덱스를 관리해야 합니다. 연결 리스트는 노드 단위로 유연하게 커지고 개별 연산 비용이 안정적이지만 참조를 위한 공간과 할당 비용이 필요합니다.

원형 배열에서는 `front`, `size`, `capacity` 사이의 불변식이 특히 중요합니다. 유효 원소 수는 항상 용량 이하이며, 논리 위치 `i`의 실제 인덱스는 앞 위치에서 `i`만큼 이동한 뒤 배열 길이로 순환시켜 계산합니다. 빈 큐와 가득 찬 큐를 인덱스만으로 구분하기 어려울 수 있으므로 크기를 별도로 보관하거나 한 칸을 항상 비워 두는 정책을 선택해야 합니다.

확장할 때에는 물리 배열을 그대로 복사하면 순환 지점 때문에 논리 순서가 뒤섞일 수 있습니다. 새 배열의 인덱스 0부터 현재 앞 원소, 그다음 원소의 순서로 복사하고 `front`를 0으로 재설정해야 합니다. 이 과정은 드물게 선형 비용을 만들지만 이후의 인큐와 디큐는 다시 빠르게 수행됩니다.

## 큐의 대표적 활용

- **전자상거래 주문 처리**: 구매자가 만든 주문을 도착 순서대로 큐에 넣고 처리합니다. 짧은 시간에 주문이 몰리더라도 큐가 생산자와 처리자의 속도 차이를 흡수합니다.
- **대기 작업과 서비스 요청**: 프린터 작업, 식당 주문, 네트워크 요청처럼 “먼저 도착한 작업을 먼저 처리”해야 하는 상황에서 순서를 유지합니다.
- **너비 우선 탐색**: 그래프나 트리에서 먼저 발견한 정점의 이웃부터 처리해 시작점에서 가까운 계층을 차례로 방문합니다.
- **메시지 버퍼**: 서로 다른 속도로 동작하는 구성요소 사이에 데이터를 잠시 저장하여 송신자가 수신자의 즉시 처리를 기다리지 않게 합니다.

큐를 선택할 때에는 엄격한 FIFO가 필요한지, 최대 대기량을 알 수 있는지, 큐가 가득 찼을 때 대기·거부·확장 중 어떤 정책을 사용할지까지 함께 정해야 합니다.

현실의 처리 시스템에서는 단순한 도착 순서 외에도 우선순위, 취소, 시간 제한이 필요할 수 있습니다. 높은 우선순위가 먼저 처리되어야 한다면 일반 큐 대신 우선순위 큐를 사용하고, 오래 기다린 작업을 제거해야 한다면 작업 식별자나 별도 색인을 함께 둡니다. 기본 FIFO 요구와 추가 정책을 구분하면 적합한 큐 종류를 선택하기 쉽습니다.
