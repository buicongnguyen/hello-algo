# 이진 트리의 배열 표현

연결 표현에서 이진 트리의 저장 단위는 `TreeNode`이며, 노드들은 참조로 서로 연결됩니다. 앞 절에서는 이 모델로 기본 연산을 설명했습니다. 하지만 트리 안의 논리적 위치와 배열 인덱스 사이에 일정한 대응 관계를 만들 수 있다면 이진 트리를 배열 하나로도 표현할 수 있습니다.

배열 표현에서는 자식 포인터를 직접 저장하지 않습니다. 대신 노드를 레벨 순서대로 배치하고 인덱스 계산식으로 부모와 자식의 위치를 알아냅니다. 이 방식의 효율은 트리 모양이 배열의 연속된 위치와 얼마나 잘 맞는지에 달려 있습니다.

## 포화 이진 트리 표현

먼저 모든 레벨이 가득 찬 포화 이진 트리를 생각해 봅니다. 레벨 순회 순서대로 노드를 배열에 저장하면 각 노드는 유일한 인덱스에 대응합니다.

레벨 순서의 규칙에서 부모–자식 인덱스 공식을 유도할 수 있습니다. **한 노드의 인덱스가 $i$이면 왼쪽 자식의 인덱스는 $2i + 1$, 오른쪽 자식의 인덱스는 $2i + 2$입니다.** 아래 그림은 이 대응 관계를 보여 줍니다.

![포화 이진 트리의 배열 표현](array_representation_of_tree.assets/array_representation_binary_tree.png)

**이 인덱스 공식은 연결 표현의 참조와 같은 역할을 합니다.** 배열의 임의 노드에서 왼쪽과 오른쪽 자식 위치를 즉시 계산할 수 있고, 자식의 인덱스를 알면 역으로 부모 인덱스도 계산할 수 있습니다. 각 노드마다 두 포인터를 저장하지 않아도 구조적 이동이 가능하다는 뜻입니다.

배열 길이를 벗어나는 계산 결과는 해당 자식이 없음을 뜻합니다. 포화 트리에서는 중간 인덱스가 비지 않으므로 유효 범위 안의 모든 위치가 실제 노드에 대응하고, 레벨이 바뀌어도 공식이 끊기지 않습니다.

## 장점과 한계

배열 표현에는 다음과 같은 장점이 있습니다.

- 연속 메모리는 캐시 친화적이므로 접근과 순회가 빠릅니다.
- 각 노드에 두 참조를 저장할 필요가 없어 포인터 공간을 절약합니다.
- 인덱스로 임의 위치에 접근하고 부모 또는 자식 위치를 상수 시간에 계산할 수 있습니다.
- 완전 트리에서는 삽입과 삭제가 배열 끝에서 일어나므로 구조 갱신이 단순합니다.

반면 다음과 같은 한계도 있습니다.

- 배열은 연속 메모리 영역이 필요하므로 매우 크거나 크기가 자주 바뀌는 트리에 덜 적합할 수 있습니다.
- 중간 위치의 삽입·삭제는 배열 이동이나 재배치를 일으켜 비용이 커질 수 있습니다.
- 트리가 희소하여 `None`이 많으면 배열의 대부분이 실제 노드를 담지 않아 공간 효율이 크게 떨어집니다.
- 한쪽으로 깊게 뻗은 트리는 깊이가 조금만 늘어도 필요한 마지막 인덱스가 빠르게 커집니다.

따라서 힙과 같은 완전 트리는 배열로 매우 효율적으로 표현할 수 있지만, 희소하거나 연결 구조가 자주 바뀌는 트리는 보통 연결 표현이 더 알맞습니다. 자료구조를 선택할 때는 접근 속도뿐 아니라 예상되는 트리 모양과 갱신 패턴을 함께 고려해야 합니다.
