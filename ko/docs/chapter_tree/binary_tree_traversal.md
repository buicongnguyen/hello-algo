# 이진 트리 순회

물리적 구조에서 보면 트리는 참조로 연결된 노드들로 이루어집니다. 따라서 각 노드를 방문하려면 루트에서 시작해 자식 참조를 따라가야 합니다. 하지만 트리는 비선형 자료구조이므로 연결 리스트처럼 한 방향으로만 진행할 수 없고, 어느 가지를 먼저 방문하며 언제 돌아올지 정하는 탐색 전략이 필요합니다.

이진 트리에서 가장 자주 사용하는 네 가지 순회는 레벨 순회, 전위 순회, 중위 순회, 후위 순회입니다. 모든 노드를 한 번씩 방문한다는 목표는 같지만 방문 순서와 보조 자료구조가 다르며, 그 차이가 각 순회의 활용 분야를 결정합니다.

## 레벨 순회

<u>레벨 순회</u>는 위에서 아래로 한 층씩 트리를 방문합니다. 같은 레벨 안에서는 노드를 왼쪽에서 오른쪽 순서로 처리합니다.

본질적으로 이것은 <u>너비 우선 순회</u>, 즉 <u>너비 우선 탐색(BFS)</u>입니다. 탐색 경계가 특정 한 가지로 깊어지지 않고 같은 거리의 노드 전체로 층층이 넓어지기 때문입니다. 루트에서 간선 수가 같은 노드가 같은 시점에 처리되므로 최단 거리나 레벨별 통계를 구할 때 자연스럽습니다.

![이진 트리의 레벨 순회](binary_tree_traversal.assets/binary_tree_bfs.png)

### 코드 구현

BFS는 보통 큐로 구현합니다. 큐는 먼저 들어온 원소를 먼저 꺼내고, BFS도 각 레벨에서 먼저 발견한 노드를 먼저 처리하므로 두 순서가 정확히 맞아떨어집니다.

각 반복에서 큐의 맨 앞 노드를 꺼내 그 값을 기록한 뒤, 존재하는 왼쪽 자식과 오른쪽 자식을 이 순서대로 큐 뒤에 넣습니다. 그 결과 현재 레벨의 모든 노드가 다음 레벨 노드보다 먼저 빠져나옵니다. 자식을 넣는 순서를 바꾸면 같은 레벨 안의 출력 순서도 바뀌지만, 레벨 자체의 위아래 순서는 유지됩니다.

### 복잡도 분석

- **시간 복잡도는 $O(n)$입니다**: 각 노드는 큐에 정확히 한 번 들어가고 한 번 나오므로 전체 시간은 $O(n)$이며, 여기서 $n$은 노드 수입니다.
- **공간 복잡도는 $O(n)$입니다**: 최악의 경우인 포화 이진 트리에서 마지막 레벨을 방문하기 직전 큐에는 최대 $(n + 1) / 2$개의 노드가 동시에 들어 있을 수 있으므로 $O(n)$ 공간을 차지합니다.

큐에 저장되는 양은 트리의 높이보다 한 레벨의 최대 너비에 좌우됩니다. 한쪽으로 긴 트리에서는 큐가 작지만, 낮고 넓은 트리에서는 마지막 부근의 많은 노드가 동시에 대기할 수 있습니다.

### 복잡도 분석

- **시간 복잡도는 $O(n)$입니다**: 각 노드를 정확히 한 번 방문하므로 $O(n)$ 시간이 필요합니다.
- **공간 복잡도는 $O(n)$입니다**: 최악의 경우 트리가 연결 리스트로 퇴화하면 재귀 깊이가 $n$에 이르고 호출 프레임이 $O(n)$ 공간을 차지합니다.

균형 트리에서는 재귀 스택 깊이가 트리 높이에 비례하여 훨씬 작지만, 복잡도 표기는 가능한 최악의 구조까지 포함합니다. 출력 결과 자체를 저장하는 배열은 모든 순회에서 별도로 선형 공간을 사용하므로, 보조 공간을 분석할 때 결과 저장 공간을 포함하는지 명확히 해야 합니다.
