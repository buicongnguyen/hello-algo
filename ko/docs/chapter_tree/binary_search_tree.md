# 이진 탐색 트리

<u>이진 탐색 트리</u>는 다음 두 조건을 동시에 만족합니다.

1. 루트 노드를 기준으로 왼쪽 서브트리의 모든 값 $<$ 루트 값 $<$ 오른쪽 서브트리의 모든 값입니다.
2. 모든 노드의 왼쪽과 오른쪽 서브트리도 이진 탐색 트리입니다. 즉 `1.`의 조건이 재귀적으로 계속 성립합니다.

이 순서 관계는 바로 옆 자식만 비교하는 조건이 아니라 서브트리 전체에 적용됩니다. 한 노드보다 작은 값은 모두 왼쪽 아래에, 큰 값은 모두 오른쪽 아래에 있어야 하므로 비교 한 번으로 탐색하지 않아도 되는 한쪽 영역을 버릴 수 있습니다.

![이진 탐색 트리](binary_search_tree.assets/binary_search_tree.png)

## 이진 탐색 트리의 연산

트리는 `BinarySearchTree` 클래스에 캡슐화하고 멤버 변수 `root`가 루트 노드를 참조합니다. 모든 연산은 순서 관계를 이용해 매 단계 두 서브트리 중 하나로만 내려갑니다. 따라서 성능은 전체 노드 수를 단순히 세는 것보다 루트에서 목적지까지의 경로 길이, 즉 트리 높이에 직접 좌우됩니다.

### 노드 탐색

목표 값 `num`을 찾을 때 `root`를 현재 노드 `cur`로 두고 다음 비교를 반복합니다.

- `cur.val < num`이면 목표는 오른쪽 서브트리에만 있을 수 있으므로 `cur = cur.right`로 이동합니다.
- `cur.val > num`이면 목표는 왼쪽 서브트리에만 있을 수 있으므로 `cur = cur.left`로 이동합니다.
- `cur.val = num`이면 목표 노드를 찾았으므로 즉시 반환할 수 있습니다.

현재 참조가 `None`이 될 때까지 같은 값이 나타나지 않으면 트리에 목표가 없습니다. 매 비교 후 탐색 범위가 한 서브트리로 줄어들기 때문에 이미 제외한 반대쪽을 다시 방문할 필요가 없습니다.

### 노드 삽입

원소 `num`을 삽입할 때도 “왼쪽 서브트리의 값은 루트보다 작고, 오른쪽 서브트리의 값은 루트보다 크다”는 관계를 보존해야 합니다. 과정은 두 단계입니다.

1. **삽입 위치 찾기**: 탐색할 때와 같은 비교를 수행하며 루트에서 아래로 이동하고, 리프를 지나 `None`에 도달할 때까지 계속합니다.
2. **새 노드 연결하기**: `num`을 담은 노드를 만든 뒤 방금 찾은 `None` 위치에 연결합니다.

![이진 탐색 트리에 노드 삽입](binary_search_tree.assets/bst_insert.png)

구현할 때는 다음 사항에 주의합니다.

- 여기서 정의한 트리는 중복 값을 저장하지 않습니다. `num`이 이미 있으면 삽입을 건너뜁니다. 중복을 허용하는 구현이라면 항상 한쪽에 두거나 개수 필드를 두는 별도 규칙이 필요합니다.
- 변수 `pre`는 이전 반복의 노드를 저장합니다. `cur`가 `None`이 되었을 때 `pre`가 바로 새 노드를 연결할 부모입니다.
- 빈 트리에 처음 삽입하는 경우에는 부모가 없으므로 새 노드가 곧 `root`가 됩니다.

새 노드는 항상 기존 리프 아래에 붙으므로 다른 서브트리의 순서는 바뀌지 않습니다. 다만 반복되는 삽입이 한 방향으로만 진행되면 높이가 커질 수 있다는 점은 별개의 구조적 문제입니다.

### 노드 제거

먼저 목표 노드를 찾은 뒤 “왼쪽 $<$ 루트 $<$ 오른쪽” 관계를 유지하며 제거합니다. 처리 방법은 노드의 자식 수, 즉 차수가 $0$, $1$, $2$ 중 무엇인지에 따라 달라집니다.

차수가 $0$이면 리프 노드이므로 부모가 그 노드를 가리키던 참조를 비우면 됩니다.

![이진 탐색 트리에서 차수 0 노드 제거](binary_search_tree.assets/bst_remove_case1.png)

차수가 $1$이면 제거할 노드의 유일한 자식을 그 노드의 원래 위치로 올립니다. 부모가 이제 그 자식을 직접 가리키게 하면 아래 서브트리를 잃지 않으면서 한 노드만 제거됩니다.

![이진 탐색 트리에서 차수 1 노드 제거](binary_search_tree.assets/bst_remove_case2.png)

차수가 $2$이면 참조를 단순히 끊을 수 없습니다. 두 서브트리 가운데 하나를 버리게 되기 때문입니다. 유효한 대체 노드는 **오른쪽 서브트리의 최솟값 노드 또는 왼쪽 서브트리의 최댓값 노드**입니다. 둘은 각각 목표 값 바로 다음 값과 바로 이전 값이므로 원래 순서를 보존합니다.

오른쪽 서브트리의 최솟값, 즉 중위 순회의 후속 노드를 선택한다고 가정합니다.

1. 제거할 노드의 중위 순회 후속 노드를 찾아 `tmp`로 둡니다. 오른쪽 자식에서 시작해 왼쪽 참조를 끝까지 따라가면 됩니다.
2. `tmp`의 값을 목표 노드에 복사한 뒤 원래 위치의 `tmp`를 제거합니다. `tmp`에는 왼쪽 자식이 없으므로 차수 $0$ 또는 $1$의 단순한 경우로 돌아갑니다.

### 중위 순회는 오름차순이다

중위 순회는 “왼쪽 $\rightarrow$ 루트 $\rightarrow$ 오른쪽” 순서를 따르고, BST는 “왼쪽 값 $<$ 루트 값 $<$ 오른쪽 값”을 보장합니다. 따라서 방문할 때마다 아직 방문하지 않은 값 가운데 더 작은 값을 먼저 만나며, **BST의 중위 순회 결과는 오름차순으로 정렬됩니다.**

이 성질을 이용하면 별도의 정렬 알고리즘 없이 전체 데이터를 $O(n)$ 시간에 정렬된 순서로 얻을 수 있습니다. 또한 범위의 하한보다 작은 서브트리나 상한보다 큰 서브트리를 건너뛰어 구간 질의를 효율적으로 만들 수 있습니다.

## 이진 탐색 트리의 효율

균형 BST는 정렬되지 않은 배열보다 탐색, 삽입, 제거를 고르게 빠르게 수행합니다. 배열은 임의 위치에 바로 접근하는 데 강하지만 값의 순서를 유지하며 갱신하려면 많은 원소를 이동해야 하고, BST는 링크를 바꾸는 대신 높이만큼 비교합니다.

표: 배열과 이진 탐색 트리의 효율 비교

| 연산 | 정렬되지 않은 배열 | 이진 탐색 트리 |
| --- | --- | --- |
| 원소 탐색 | $O(n)$ | $O(\log n)$ |
| 원소 삽입 | $O(1)$ | $O(\log n)$ |
| 원소 제거 | $O(n)$ | $O(\log n)$ |

표의 BST 복잡도는 트리가 균형에 가깝다는 전제입니다. 이상적인 경우 최대 $O(\log n)$번 아래로 이동하면 노드를 찾지만, 불리한 삽입·삭제 순서는 트리를 완전히 기울게 만들 수 있습니다. 그러면 BST가 연결 리스트로 퇴화하고 모든 주요 연산이 $O(n)$으로 느려집니다.

![이진 탐색 트리의 퇴화](binary_search_tree.assets/bst_degradation.png)

순서가 이미 정렬된 데이터를 그대로 삽입하면 매 새 값이 이전 노드의 같은 방향 자식이 되므로 이런 퇴화가 쉽게 발생합니다. 단순 BST는 순서 조건만 유지할 뿐 높이를 자동으로 제한하지 않습니다. 안정적인 최악 성능이 필요하면 AVL 트리나 레드-블랙 트리처럼 갱신 후 균형을 복구하는 구조를 사용합니다.

## 이진 탐색 트리의 대표 활용

- 시스템의 다단계 인덱스로 사용하여 탐색, 삽입, 제거를 효율적으로 지원합니다.
- 일부 탐색 알고리즘과 정렬된 집합·맵의 기반 구조로 사용합니다.
- 데이터 스트림을 순서대로 유지하면서 최솟값, 최댓값, 이전·다음 원소 또는 특정 범위를 질의합니다.
- 중위 순회로 정렬된 스냅샷을 만들거나, 순위와 서브트리 크기 같은 보조 정보를 더해 순서 통계 질의를 지원합니다.

실제 라이브러리는 중복 키 처리, 비교 함수, 반복자 무효화, 동시성 같은 정책도 명확히 정의해야 합니다. 이진 탐색 트리의 핵심 불변식은 모든 갱신 뒤에도 각 노드의 왼쪽 전체가 작고 오른쪽 전체가 크다는 것이며, 테스트는 이 조건과 부모–자식 연결이 함께 보존되는지 확인해야 합니다.
