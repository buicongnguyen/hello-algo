# 연습문제

## 개념 복습

아래 문제들은 충돌이 생겨도 실제 키가 보존되는지, 용량 변화 뒤 왜 모든 위치를 다시 계산해야 하는지, 개방 주소법의 삭제가 탐사 경로에 어떤 영향을 주는지를 단계별로 확인합니다. 각 답을 쓸 때는 최종 배열만 적지 말고 해시 인덱스와 비교 순서를 함께 추적하세요.

### 해시 충돌 뒤의 조회

버킷이 5개인 해시 테이블이 해시 함수 $h(x)=x \bmod 5$를 사용합니다. 충돌한 원소는 해당 버킷의 리스트 뒤에 차례로 저장합니다. `[1, 6, 11, 7]`을 순서대로 삽입하세요.

<!-- numbered-subquestions -->

1. 버킷 0부터 4까지의 내용을 쓰세요.
2. 6을 조회할 때 먼저 어느 버킷을 확인하고, 어떤 원소를 어떤 순서로 비교합니까?
3. 뒤에 삽입한 원소가 앞의 원소를 덮어씁니까? 이 충돌 해결 방식으로 설명하세요.

??? success "정답"

    1. $1\bmod5=6\bmod5=11\bmod5=1$이고 $7\bmod5=2$이므로 버킷은 다음과 같습니다.

        ```text
        0: []
        1: [1, 6, 11]
        2: [7]
        3: []
        4: []
        ```

    2. 6의 시작 위치는 버킷 1입니다. 리스트에서 1을 먼저 비교하고, 다음 원소 6에서 목표를 찾습니다.

    3. 같은 해시 값은 같은 버킷을 뜻할 뿐 실제 키가 같다는 뜻은 아닙니다. 분리 연결법은 충돌한 1, 6, 11을 모두 보관하고 조회 때 실제 값을 비교하므로 서로 덮어쓰지 않습니다.

### 해시 테이블 확장 뒤의 위치

분리 연결법 해시 테이블에 원래 버킷이 5개이고 함수는 $h(x)=x\bmod5$입니다. 키 `[1, 6, 11]`은 모두 버킷 1에 있습니다.

이제 버킷을 7개로 확장하여 함수가 $h(x)=x\bmod7$이 됩니다.

<!-- numbered-subquestions -->

1. 1, 6, 11의 새 버킷 번호를 계산하세요.
2. 확장 뒤 어느 버킷에 원소가 있습니까?
3. 이전 버킷 1의 리스트를 새 버킷 1에 그대로 복사해도 됩니까? 계산 결과로 설명하세요.

??? success "정답"

    1. 새 위치는 다음과 같습니다.

        - $1\bmod7=1$
        - $6\bmod7=6$
        - $11\bmod7=4$

    2. 버킷 1에는 1, 버킷 4에는 11, 버킷 6에는 6이 저장됩니다. 세 키가 서로 다른 위치로 흩어집니다.

    3. 그대로 복사할 수 없습니다. 버킷 수가 바뀌면 나머지 결과도 바뀔 수 있으므로 모든 키를 새 용량으로 다시 계산해야 합니다. 이전 리스트를 버킷 1에 두면 이후 조회는 6을 버킷 6에서, 11을 버킷 4에서 찾다가 실패합니다.

### 6을 지운 뒤에도 11을 찾을 수 있는가?

인덱스 `0–4`인 다섯 칸의 해시 테이블이 $h(x)=x\bmod5$를 사용합니다. 충돌하면 시작 인덱스부터 오른쪽으로 이동해 첫 빈 칸에 저장합니다. `[1, 6, 11]`을 순서대로 삽입하세요.

<!-- numbered-subquestions -->

1. 각 수가 최종적으로 저장되는 인덱스는 어디입니까?
2. 11을 조회할 때 어떤 인덱스를 차례로 확인합니까?
3. 6을 삭제하면서 그 위치를 “한 번도 사용하지 않은 빈 칸”으로 바꾸고, 조회가 빈 칸에서 멈춘다고 가정합니다. 이후 11의 조회 결과는 올바릅니까? 문제를 어떻게 피할 수 있습니까?

??? success "정답"

    1. 1은 인덱스 1에 저장됩니다. 6도 1로 해시되므로 충돌 뒤 인덱스 2에 저장됩니다. 11은 1과 2를 지나 인덱스 3에 저장됩니다.

    2. 인덱스 `1, 2, 3`을 차례로 확인하고 3에서 11을 찾습니다.

    3. 인덱스 2를 미사용 빈 칸으로 만들면 조회가 1을 확인한 뒤 2에서 멈추어 11이 없다고 잘못 판단합니다. 삭제된 위치에는 묘비 표식을 남겨 조회가 계속 진행하게 해야 합니다. 이후 삽입은 그 위치를 재사용할 수 있습니다.

### 두 문자열의 문자 빈도 비교

영문 소문자로만 이루어진 문자열 `s`와 `t`가 주어집니다. `s`의 문자를 원하는 순서로 재배열할 수 있지만 문자를 추가, 삭제, 교체할 수는 없습니다.

재배열한 `s`로 `t`를 만들 수 있으면 `true`, 아니면 `false`를 반환하세요. 정렬하지 말고 해시 테이블에 각 문자의 출현 횟수를 기록하세요.

??? tip "힌트"

    1. 두 문자열의 길이가 다르면 각 문자의 개수가 같을 수 없습니다.
    2. `s`를 순회하며 각 문자 카운트를 증가시킵니다.
    3. `t`를 순회하며 대응 카운트를 감소시킵니다. 마지막에 모든 카운트가 0일 때만 두 문자열의 문자 구성이 같습니다.

[LeetCode](https://leetcode.com/problems/valid-anagram/){ .rounded-button .exercise-button target="_blank" rel="noopener noreferrer" }

문자 빈도 문제를 구현한 뒤에는 빈 문자열, 길이가 다른 문자열, 모든 문자가 같은 문자열, 같은 문자 집합이지만 횟수가 다른 문자열을 추가로 시험하세요. 카운트를 감소시키는 도중 음수가 되면 즉시 실패하도록 최적화할 수도 있습니다. 영문 소문자만 허용된다는 조건을 이용하면 고정 배열도 가능하지만, 이 연습에서는 키 집합을 일반화할 수 있도록 해시 테이블의 추가·조회·갱신 흐름을 확인하는 데 초점을 둡니다.

마지막에는 시간과 공간 사용량도 직접 설명해 보세요.
