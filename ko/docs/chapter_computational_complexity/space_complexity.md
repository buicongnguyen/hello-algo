# 공간 복잡도

<u>공간 복잡도</u>는 데이터 크기가 증가할 때 알고리즘이 차지하는 메모리 공간의 성장 추세를 측정합니다. 시간 복잡도에서 “실행 시간”을 “점유 메모리”로 바꾸어 생각하면 이해하기 쉽습니다.

## 알고리즘과 관련된 공간

알고리즘 실행 중 사용되는 메모리는 주로 다음 세 종류입니다.

- **입력 공간**: 알고리즘의 입력 데이터를 저장합니다.
- **임시 공간**: 실행 중 생성되는 변수, 객체, 함수 문맥 등을 저장합니다.
- **출력 공간**: 알고리즘이 만들어 낸 결과 데이터를 저장합니다.

일반적으로 공간 복잡도를 계산할 때는 “임시 공간 + 출력 공간”을 대상으로 하고, 문제에서 이미 주어진 입력을 저장하는 공간은 제외합니다. 다만 입력을 복사하거나 변경 가능한 새 구조를 만들면 그 복사본은 임시 공간에 포함됩니다.

임시 공간은 다시 세 부분으로 나눌 수 있습니다.

- **임시 데이터**: 실행 중의 상수, 변수와 객체를 저장합니다.
- **스택 프레임 공간**: 호출된 함수의 문맥을 저장합니다. 함수가 호출될 때마다 시스템이 호출 스택 위에 새 프레임을 만들고, 함수가 반환되면 해제합니다.
- **명령어 공간**: 컴파일된 프로그램 명령을 저장하며, 보통 복잡도 계산에서는 무시합니다.

따라서 분석에서는 주로 **임시 데이터, 스택 프레임, 출력 데이터**를 확인합니다.

### 로그 차수 $O(\log n)$

로그 차수는 분할 정복 알고리즘에 흔합니다. 병합 정렬에서 길이 $n$의 배열을 매 재귀 단계마다 절반으로 나누면 높이가 $\log n$인 재귀 트리가 만들어지고 호출 스택은 $O(\log n)$ 공간을 사용합니다.

숫자를 문자열로 바꾸는 경우도 예입니다. 양의 정수 $n$의 자릿수는 $\lfloor \log_{10} n \rfloor + 1$이고, 만들어지는 문자열 길이 역시 $\lfloor \log_{10} n \rfloor + 1$이므로 공간 복잡도는 $O(\log_{10} n + 1) = O(\log n)$입니다.

## 시간과 공간의 교환

이상적으로는 시간 복잡도와 공간 복잡도를 모두 최소화하고 싶지만, 실제로 두 목표를 동시에 최적화하기는 어렵습니다.

**시간 복잡도를 낮추려면 공간을 더 사용하는 경우가 많고, 공간 복잡도를 낮추면 시간이 늘어날 수 있습니다.** 메모리를 희생해 실행 속도를 높이는 것을 “공간으로 시간을 바꾼다”고 하고, 반대 선택을 “시간으로 공간을 바꾼다”고 합니다.

어느 쪽을 선택할지는 시스템의 제약에 달려 있습니다. 일반적인 서버나 사용자 애플리케이션에서는 응답 시간이 더 귀해 캐시, 해시 테이블, 인덱스처럼 공간을 사용해 시간을 줄이는 전략이 흔합니다. 반대로 입력이 매우 크거나 장치 메모리가 제한된 경우에는 중간 결과를 다시 계산하더라도 최고 메모리 사용량을 낮추는 편이 안전합니다.
