# 병합 정렬

<u>병합 정렬</u>은 분할 정복을 바탕으로 하며 서로 대칭적인 두 단계로 구성됩니다.

1. **분할**: 배열을 가운데에서 재귀적으로 나누어 긴 배열 하나의 정렬 문제를 여러 짧은 배열의 정렬 문제로 바꿉니다.
2. **병합**: 부분 배열이 원소 하나가 되면 분할을 멈춥니다. 아래에서 위로 정렬된 두 부분 배열을 계속 합쳐 더 긴 정렬 배열을 만듭니다.

![분할과 병합의 두 단계](merge_sort.assets/merge_sort_overview.png)

## 알고리즘 과정

분할 단계에서는 `mid`를 계산하고 왼쪽 구간 `[left, mid]`와 오른쪽 구간 `[mid + 1, right]`를 재귀적으로 처리합니다. 구간 길이가 1이 될 때까지 반복합니다. 길이 1인 구간은 별도의 작업 없이 이미 정렬되어 있습니다.

병합 단계에서는 정렬된 두 구간의 시작에 포인터를 하나씩 둡니다. 매번 더 작은 원소를 임시 배열에 기록합니다. 한쪽이 먼저 끝나면 다른 쪽의 남은 원소를 그대로 복사하고, 마지막에 임시 결과를 원래 배열에 되돌려 씁니다.

## 알고리즘 특성

- **시간 복잡도 $O(n \log n)$, 비적응형**: 분할 단계는 높이 $\log n$의 재귀 트리를 만들고, 각 층에서 처리하는 원소 수의 합은 $n$이므로 전체가 $O(n \log n)$입니다. 입력이 이미 정렬되어 있어도 기본 구현은 같은 분할과 병합을 수행합니다.
- **공간 복잡도 $O(n)$, 비제자리 정렬**: 재귀 스택 깊이 $\log n$은 $O(\log n)$을 사용하고, 병합용 보조 배열은 입력 길이에 비례하여 $O(n)$을 사용합니다.
- **안정 정렬**: 두 원소가 같을 때 왼쪽 구간의 원소를 먼저 선택하면 원래 상대적 순서를 유지합니다. 비교 조건을 반대로 쓰면 같은 알고리즘도 안정성을 잃을 수 있습니다.

병합 정렬은 데이터 분포와 무관하게 시간 상한이 안정적이라는 장점이 있습니다. 퀵 정렬처럼 피벗 선택에 따라 제곱 시간이 되는 경우가 없으므로 예측 가능한 지연이 중요한 상황에 적합합니다. 반면 배열에서는 매 병합마다 연속된 보조 공간과 데이터 복사가 필요합니다.

## 연결 리스트 정렬

병합 정렬은 연결 리스트에 특히 잘 맞으며 정렬 자체의 추가 공간을 $O(1)$까지 줄일 수 있습니다.

- **분할 단계**는 재귀 대신 반복을 사용하여 호출 스택 프레임을 없앨 수 있습니다. 빠른 포인터와 느린 포인터로 중간을 찾거나, 아래에서 위로 길이 1, 2, 4인 구간을 차례로 병합할 수 있습니다.
- **병합 단계**는 노드 사이의 포인터만 갱신합니다. 결과를 담기 위한 새 리스트나 배열을 만들 필요가 없습니다.

배열에서는 원소를 임시 공간에 복사해야 하지만 연결 리스트에서는 다음 노드 참조를 바꾸는 것만으로 정렬된 두 목록을 이어 붙일 수 있습니다. 임의 접근은 느리지만 병합은 각 목록을 앞에서부터 한 번만 순회하므로 이 약점의 영향을 받지 않습니다.

연결 리스트용 최적 구현은 배열 버전보다 복잡하지만, 짧은 부분으로 나누고 순서대로 병합한다는 원리는 같습니다.
