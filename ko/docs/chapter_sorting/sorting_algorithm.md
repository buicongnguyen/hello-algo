# 정렬 알고리즘

<u>정렬 알고리즘</u>은 데이터 집합을 정해진 순서로 배치합니다. 정렬된 데이터는 무질서한 데이터보다 검색, 분석, 처리가 쉬운 경우가 많아 매우 널리 사용됩니다.

아래 그림처럼 정렬 대상은 정수, 부동소수점수, 문자, 문자열, 복잡한 객체가 될 수 있습니다. 순서 규칙도 요구 사항에 따라 수의 크기, ASCII 코드 순서, 또는 애플리케이션이 정의한 비교 규칙으로 정할 수 있습니다.

## 평가 기준

**실행 효율**: 시간 복잡도가 낮아야 할 뿐 아니라 비교, 대입, 교환의 전체 횟수도 작아야 상수 계수를 줄일 수 있습니다. 데이터가 클수록 실행 효율의 차이는 더 중요해집니다.

**제자리 속성**: <u>제자리 정렬</u>은 입력 크기에 비례하는 보조 배열을 만들지 않고 원래 배열을 직접 조작합니다. 메모리를 절약하며 실제로는 데이터 복사 횟수도 줄이는 경우가 많습니다.

**안정성**: <u>안정 정렬</u>은 키가 같은 원소들의 상대적 순서를 정렬 뒤에도 보존합니다.

안정성은 여러 기준으로 단계적으로 정렬할 때 필요합니다. 학생 표가 이미 이름순으로 정렬되어 있고 다시 나이순으로 정렬한다고 가정합시다. <u>불안정 정렬</u>은 나이가 같은 두 학생의 순서를 뒤집어 기존 이름순을 잃게 만들 수 있습니다.

```shell
# 입력 데이터는 이름순으로 정렬되어 있습니다
# (이름, 나이)
  ('A', 19)
  ('B', 18)
  ('C', 21)
  ('D', 19)
  ('E', 23)

# 불안정한 알고리즘으로 나이순 정렬을 수행한다고 가정합니다.
# 결과에서 ('D', 19)와 ('A', 19)의 상대적 위치가 바뀌므로
# 입력 데이터가 이름순이었다는 성질이 사라집니다.
  ('B', 18)
  ('D', 19)
  ('A', 19)
  ('C', 21)
  ('E', 23)
```

**적응성**: <u>적응형 정렬</u>은 입력에 이미 존재하는 순서 정보를 이용하여 계산량을 줄입니다. 따라서 적응형 알고리즘의 최선 시간 복잡도는 보통 평균 시간 복잡도보다 좋습니다.

**비교 기반 여부**: <u>비교 기반 정렬</u>은 비교 연산자 $<$, $=$, $>$로 원소의 상대적 순서를 정합니다. 이 모델의 일반적인 이론적 최적 한계는 $O(n \log n)$입니다. <u>비교하지 않는 정렬</u>은 값의 범위나 자릿수 구조를 활용하여 $O(n)$을 달성할 수 있지만 적용 범위가 더 제한적입니다.

## 이상적인 정렬 알고리즘

이상적인 알고리즘은 동시에 **빠르고, 제자리이며, 안정적이고, 적응형이고, 널리 적용 가능**해야 합니다. 현재까지 이 특성을 모두 완벽히 결합한 정렬 알고리즘은 없습니다.

따라서 선택은 데이터 크기, 메모리 제한, 키 분포, 안정성 요구, 입력이 이미 얼마나 정렬되어 있는지를 함께 고려해야 합니다. 예를 들어 메모리가 매우 제한되면 제자리 속성이 중요하고, 여러 열을 차례로 정렬한다면 안정성이 필요합니다. 값의 범위가 좁은 정수라면 비교하지 않는 방법도 강력한 선택이 됩니다.

평가할 때는 점근 복잡도 하나만 보아서는 안 됩니다. 같은 `O(n log n)` 알고리즘도 메모리 접근의 연속성, 재귀 호출 수, 실제 비교와 이동 횟수에 따라 체감 성능이 달라집니다. 입력이 작거나 거의 정렬되어 있다면 이론적으로 더 단순한 방법이 더 빠를 수도 있습니다. 반대로 데이터가 메모리에 다 들어가지 않으면 외부 저장 장치의 읽기·쓰기 패턴이 핵심 기준이 됩니다. 안정성과 제자리 속성 역시 단순한 부가 기능이 아니라 응용의 정확성과 자원 한계를 결정하는 요구 사항입니다.
