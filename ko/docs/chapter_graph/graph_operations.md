# 그래프 기본 연산

그래프 연산은 간선 연산과 정점 연산으로 나눌 수 있습니다. 구현 방법은 그래프를 인접 행렬로 표현하는지 인접 리스트로 표현하는지에 따라 달라집니다.

## 인접 행렬 기반 구현

정점이 $n$개인 무방향 그래프에서 연산은 다음과 같습니다.

- **간선 추가 또는 삭제**: 인접 행렬의 해당 원소를 직접 수정하므로 $O(1)$이 걸립니다. 무방향 그래프이므로 양방향을 함께 갱신해야 합니다.
- **정점 추가**: 행렬 끝에 행과 열을 하나씩 추가하고 모두 $0$으로 채우므로 $O(n)$이 걸립니다.
- **정점 삭제**: 행과 열을 하나씩 삭제합니다. 최악의 경우 첫 행과 첫 열을 삭제하면 $(n-1)^2$개 원소를 위와 왼쪽으로 옮겨야 하므로 $O(n^2)$이 걸립니다.
- **초기화**: 정점이 $n$개이면 길이 $n$의 `vertices` 목록을 $O(n)$에 만들고, $n \times n$ 크기의 `adjMat` 행렬을 $O(n^2)$에 만듭니다.

## 인접 리스트 기반 구현

정점이 $n$개이고 간선이 $m$개인 무방향 그래프에서 연산은 다음과 같습니다.

- **간선 추가**: 해당 정점의 리스트 끝에 간선을 추가하므로 $O(1)$이 걸립니다. 무방향 그래프에서는 양방향 간선을 모두 추가합니다.
- **간선 삭제**: 정점 리스트에서 지정한 간선을 찾아 삭제하므로 $O(m)$이 걸립니다. 양방향을 모두 삭제해야 합니다.
- **정점 추가**: 새 정점을 첫 노드로 하는 목록을 인접 리스트에 추가하므로 $O(1)$이 걸립니다.
- **정점 삭제**: 전체 인접 리스트를 순회하며 지정한 정점을 포함하는 모든 간선을 삭제하므로 $O(n + m)$이 걸립니다.
- **초기화**: 인접 리스트에 정점 $n$개와 간선 $2m$개를 만들므로 $O(n + m)$이 걸립니다.

## 성능 비교

그래프에 정점 $n$개와 간선 $m$개가 있다고 가정합니다. 다음 표는 인접 행렬, 연결 리스트 기반 인접 리스트, 각 목록을 해시 테이블로 바꾼 인접 리스트의 시간과 공간 효율을 비교합니다.

| 연산 | 인접 행렬 | 인접 리스트(연결 리스트) | 인접 리스트(해시 테이블) |
| --- | --- | --- | --- |
| 두 정점의 인접 여부 확인 | $O(1)$ | $O(n)$ | $O(1)$ |
| 간선 추가 | $O(1)$ | $O(1)$ | $O(1)$ |
| 간선 삭제 | $O(1)$ | $O(n)$ | $O(1)$ |
| 정점 추가 | $O(n)$ | $O(1)$ | $O(1)$ |
| 정점 삭제 | $O(n^2)$ | $O(n + m)$ | $O(n)$ |
| 메모리 공간 | $O(n^2)$ | $O(n + m)$ | $O(n + m)$ |

표만 보면 해시 테이블 기반 인접 리스트가 시간과 공간 모두에서 가장 좋아 보입니다. 하지만 실제로 인접 행렬의 간선 연산은 배열 원소에 한 번 접근하거나 대입할 뿐이라 상수 계수가 매우 작습니다. 일반적으로 인접 행렬은 **공간으로 시간을 바꾸는 방식**, 인접 리스트는 **시간으로 공간을 바꾸는 방식**을 보여 줍니다.

실제 자료구조에서는 연산을 하나의 원자적인 갱신으로 다루는 것이 중요합니다. 무방향 간선을 추가하다가 한쪽 목록만 바뀌거나, 정점을 삭제한 뒤 연결된 간선 일부가 남으면 표현의 불변식이 깨집니다. 따라서 입력 정점의 존재 여부와 자기 간선 허용 정책을 먼저 검사하고, 양방향 변경을 모두 마친 뒤 성공을 반환해야 합니다.

성능 표의 점근적 복잡도만으로 구현을 고르기보다 그래프의 예상 크기와 밀도, 갱신 빈도, 조회 패턴도 함께 살펴야 합니다. 작은 조밀 그래프에서는 행렬이 단순하고 캐시 친화적일 수 있으며, 큰 희소 그래프에서는 인접 리스트가 메모리 사용량을 크게 줄입니다. 반복 순서가 결과 재현성에 중요하면 인접 정점의 저장 순서도 명시해야 합니다.
