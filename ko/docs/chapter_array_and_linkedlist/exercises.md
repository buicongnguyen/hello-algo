# 연습문제

## 개념 복습

### 배열과 연결 리스트는 원소를 어떻게 찾을까?

배열과 단일 연결 리스트가 모두 `[A, B, C, D, E]`를 저장합니다. 네 번째 원소 `D`에 접근하세요.

1. 배열은 어떤 인덱스를 바로 사용할 수 있습니까?
2. 머리 노드 `A`에서 어떤 노드를 차례로 방문합니까?
3. 요청 위치가 뒤로 갈수록 각 자료 구조의 단계 수는 어떻게 달라집니까? 위치로 반복해서 접근할 때에는 어느 쪽이 더 적합하며, 그 이유는 무엇입니까?

??? success "정답"

    1. 0부터 시작하는 인덱스에서 네 번째 원소의 인덱스는 3이므로 배열은 `arr[3]`을 $O(1)$ 시간에 바로 접근합니다.

    2. 단일 연결 리스트는 반드시 머리 노드에서 시작합니다. 방문 경로는 `A → B → C → D`이며 `next`를 세 번 따라가야 합니다.

    3. 배열은 시작 주소와 인덱스로 원소의 주소를 계산하므로 위치가 뒤로 가도 직접 접근할 수 있습니다.
        단일 연결 리스트에서 $k$번째 노드에 접근하려면 머리부터 `next`를 $k-1$번 따라가야 하므로 최악의 시간 복잡도는 $O(n)$입니다.
        따라서 위치로 원소를 반복 조회할 때에는 배열이 더 적합합니다. 다만 이 비교는 위치 접근만 다루며, 연결 리스트가 모든 연산에서 더 느리다는 뜻은 아닙니다.

### 배열과 연결 리스트는 원소를 어떻게 삽입할까?

배열 `[A, B, C, D, _]`에는 한 칸이 남아 있습니다. 연결 리스트는 `A → B → C → D`이고 `B`의 참조를 이미 알고 있습니다. `B` 뒤에 `X`를 넣으세요.

1. 배열에서 어떤 원소를 이동해야 합니까? 삽입 뒤의 배열을 쓰세요.
2. 연결 리스트에서는 `X.next`와 `B.next`를 어떤 순서로 갱신해야 합니까? 삽입 뒤의 연결 리스트를 쓰세요.
3. 삽입 효율을 비교할 때 “노드 `B`의 참조를 이미 알고 있다”는 조건이 왜 중요합니까?

??? success "정답"

    1. 배열은 먼저 `D`를 오른쪽으로 한 칸, 이어서 `C`를 오른쪽으로 한 칸 옮깁니다.
        그런 다음 인덱스 2에 `X`를 넣으면 `[A, B, X, C, D]`가 됩니다.

    2. 원래 `B.next`는 `C`를 가리킵니다. 먼저 `X.next = B.next`로 `X`가 `C`를 가리키게 하고,
        그다음 `B.next = X`로 바꾸면 `A → B → X → C → D`가 됩니다.
        원래 연결을 저장하지 않은 채 `B.next`부터 덮어쓰면 `C` 이후의 노드에 도달할 수 없게 될 수 있습니다.

    3. `B`의 위치를 이미 안다면 두 링크만 바꾸므로 삽입은 $O(1)$ 시간에 끝납니다.
        반대로 머리에서 `B`를 먼저 찾아야 한다면 탐색에만 $O(n)$ 시간이 걸릴 수 있습니다.

### 리스트의 용량은 어떻게 늘어날까?

배열 기반 리스트 `[A, B, C]`의 `size = 3`, `capacity = 4`이고 가득 차면 용량을 두 배로 늘립니다. `D`와 `E`를 차례로 추가하면 어떻게 됩니까?

1. `D`를 추가한 뒤 리스트의 길이와 용량은 얼마입니까? 이때 용량 확장이 필요합니까?
2. 이어서 `E`를 추가하면 용량은 얼마가 되며, 기존 원소를 몇 개 복사해야 합니까?
3. 기반 배열 자체의 길이는 바꿀 수 없는데도 리스트의 용량이 늘어나는 것처럼 보이는 이유는 무엇입니까?

??? success "정답"

    1. `D`는 마지막 빈칸에 들어갑니다. 내용은 `[A, B, C, D]`, `size = 4`, `capacity = 4`가 되며 아직 확장은 필요하지 않습니다.

    2. `E`를 추가할 때에는 빈칸이 없으므로 용량이 8인 새 배열을 만듭니다.
        기존 원소 `A`, `B`, `C`, `D` 네 개를 새 배열에 복사한 다음 `E`를 추가하므로 결과는 `size = 5`, `capacity = 8`입니다.

    3. 원래 배열 자체가 커지는 것은 아닙니다. 리스트가 더 큰 새 배열을 만들고 기존 원소를 복사한 뒤,
        내부 저장소를 새 배열로 교체합니다. 이 세부 구현을 감추기 때문에 사용자에게는 리스트의 용량이 늘어난 것처럼 보입니다.

## 프로그래밍 연습

### 배열로 저장한 큰 정수에 1 더하기

`digits`는 음이 아닌 정수의 십진수 각 자릿수를 왼쪽부터 저장합니다. 예를 들어 `[3, 0, 8]`은 308을 뜻합니다.
정수 0은 `[0]`으로 나타내며, 그 밖의 입력에서는 첫 자릿수가 0이 아닙니다.

세로셈을 흉내 내어 이 정수에 1을 더하고 같은 배열 형식으로 결과를 반환하세요.
`digits`를 직접 수정해도 되며, 맨 앞에 새로운 올림이 생기면 더 긴 배열을 반환할 수 있습니다.

입력 배열의 길이에 비례하는 시간 안에 처리하고, 올림이 더 이상 없으면 남은 앞쪽 자릿수를 다시 방문하지 않아도 됩니다.

??? tip "힌트"

    1. 일반적인 세로셈처럼 배열의 마지막 자릿수부터 시작합니다.
    2. 현재 자릿수가 9보다 작으면 1을 더한 뒤 즉시 반환합니다.
    3. 현재 자릿수가 9이면 0으로 바꾸고 왼쪽으로 계속합니다. 모든 자릿수가 9였다면 맨 앞에 1을 둡니다.

[LeetCode](https://leetcode.com/problems/plus-one/)

### 단일 연결 리스트 뒤집기

단일 연결 리스트의 머리 노드 `head`가 주어집니다. 각 노드는 값과 다음 노드를 가리키는 `next` 참조를 가집니다.

반복문을 사용해 노드 사이의 모든 연결 방향을 뒤집고 새로운 머리 노드를 반환하세요.
새 연결 리스트 노드를 만들면 안 됩니다.

??? tip "힌트"

    1. 먼저 종이에 연결된 노드 세 개와 포인터 `prev`, `cur`를 그려 봅니다.
    2. `cur.next`를 바꾸기 전에 원래 다음 노드를 `nxt = cur.next`에 저장합니다.
    3. `cur.next`를 뒤집은 뒤 `prev = cur`, 이어서 `cur = nxt`로 갱신해 원래 리스트의 다음 노드로 진행합니다.

[LeetCode](https://leetcode.com/problems/reverse-linked-list/)
