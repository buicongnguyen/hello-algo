# 연결 리스트

실행 중인 시스템의 빈 메모리는 여러 곳에 흩어져 있을 수 있습니다. 배열은 연속된 메모리 영역이 필요하므로 전체 여유 메모리가 충분해도 매우 큰 배열을 할당하지 못하는 경우가 있습니다. 연결 리스트는 이런 상황에서 더 유연합니다.

**연결 리스트**는 노드 객체로 이루어진 선형 자료구조입니다. 노드는 참조로 연결되고 각 참조는 다음 노드의 위치를 기록합니다. 따라서 노드가 연속되지 않은 주소에 있어도 됩니다.

배열이 물리적인 메모리 순서로 논리적 순서를 표현한다면, 연결 리스트는 노드가 저장한 참조로 논리적 순서를 표현합니다. 다음 노드의 주소만 정확하다면 두 노드가 메모리에서 멀리 떨어져 있어도 하나의 연속된 목록으로 탐색할 수 있습니다.

![연결 리스트의 정의와 저장 방식](linked_list.assets/linkedlist_definition.png)

각 **노드**는 값과 다음 노드를 가리키는 참조로 구성됩니다.

- 첫 노드는 **머리 노드**, 마지막 노드는 **꼬리 노드**입니다.
- 꼬리 노드는 Python의 `None` 같은 빈 값을 가리킵니다.
- C, C++, Go, Rust에서는 여기서 말하는 참조를 보통 포인터로 표현합니다.
- 각 노드가 참조를 추가로 저장하므로 같은 수의 값을 저장할 때 연결 리스트가 배열보다 많은 메모리를 쓰는 경우가 많습니다.

머리 노드에 대한 참조를 잃으면 리스트 전체에 접근할 경로도 잃을 수 있습니다. 반대로 머리 노드만 알고 있으면 `next`를 반복해서 따라가며 모든 노드를 방문할 수 있습니다. 이 단방향 연결이 단일 연결 리스트의 핵심 불변식입니다.

그림에서 노드는 서로 나란히 보이지만 실제 메모리 주소가 그림 순서와 같을 필요는 없습니다. 운영체제와 메모리 할당자는 각 노드를 만들 때 이용 가능한 위치를 선택합니다. 연결 리스트가 유지해야 하는 것은 물리적인 이웃 관계가 아니라 각 `next`가 논리적으로 다음 노드를 정확히 가리킨다는 조건입니다. 노드 하나의 연결을 잘못 덮어쓰면 그 뒤에 있는 전체 구간에 접근할 수 없게 될 수 있으므로 참조를 바꾸는 순서가 중요합니다.

```python
class ListNode:
    """단일 연결 리스트의 노드입니다."""

    def __init__(self, value: int):
        self.value = value
        self.next: ListNode | None = None
```

## 기본 연산

### 연결 리스트 초기화

노드를 하나씩 만들고 `next` 관계를 설정합니다. 리스트는 여러 독립 객체로 이루어지지만 보통 머리 노드로 전체 리스트를 나타냅니다.

초기화 과정에서는 먼저 서로 연결되지 않은 노드를 만든 다음 앞 노드의 `next`를 뒤 노드에 연결합니다. 마지막 노드의 `next`는 빈 참조로 남겨 순회의 종료 조건을 표시합니다. 비어 있는 연결 리스트는 머리 참조 자체가 빈 값이며, 원소가 하나뿐인 리스트에서는 머리와 꼬리가 같은 노드를 뜻합니다. 이 두 경계 사례는 삽입과 삭제 코드를 작성할 때 별도로 확인해야 합니다.

```python
class ListNode:
    def __init__(self, value: int):
        self.value = value
        self.next: ListNode | None = None


n0 = ListNode(1)
n1 = ListNode(3)
n2 = ListNode(2)
n3 = ListNode(5)
n4 = ListNode(4)
n0.next = n1
n1.next = n2
n2.next = n3
n3.next = n4
```

### 노드 삽입

인접한 `n0`와 `n1` 사이에 노드 `P`를 삽입한다고 합시다. 이미 `n0`에 대한 참조가 있다면 두 연결만 바꾸면 되므로 삽입에 $O(1)$ 시간이 걸립니다.

배열에 같은 위치의 원소를 삽입하면 뒤쪽 원소를 옮겨야 하므로 $O(n)$ 시간이 걸립니다. 연결 리스트의 장점은 삽입 위치를 이미 알고 있을 때 데이터 이동 없이 두 참조만 수정한다는 데 있습니다.

연결을 갱신할 때에는 새 노드가 원래 다음 노드를 먼저 기억하게 해야 합니다. `n0.next`를 즉시 새 노드로 바꾸고 원래 다음 노드의 주소를 따로 보관하지 않았다면 이후 구간을 다시 찾을 방법이 없습니다. 머리 앞에 삽입하는 경우에는 새 노드가 기존 머리를 가리키게 한 뒤 머리 참조를 새 노드로 바꿉니다. 꼬리 뒤에 삽입하려면 꼬리 참조를 별도로 관리하거나 머리에서 끝까지 순회해야 합니다.

![연결 리스트에 노드를 삽입하는 예](linked_list.assets/linkedlist_insert_node.png)

```python
class ListNode:
    def __init__(self, value: int):
        self.value = value
        self.next: ListNode | None = None


def insert(n0: ListNode, node: ListNode) -> None:
    node.next = n0.next
    n0.next = node
```

### 노드 삭제

`n0` 바로 다음 노드를 삭제하려면 `n0.next`가 그 노드를 건너뛰고 다음 노드를 가리키게 합니다. 삭제된 노드가 이전 참조를 계속 가지고 있을 수 있지만 머리 노드부터 순회할 때는 더 이상 도달할 수 없습니다.

언어가 자동 메모리 관리를 제공하면 더 이상 도달할 수 없는 노드는 나중에 회수됩니다. 수동 메모리 관리 언어에서는 노드가 차지한 공간을 적절히 해제해야 하며, 아직 사용 중인 노드를 너무 일찍 해제하지 않도록 주의해야 합니다.

삭제는 실제로 뒤쪽 모든 노드를 움직이는 일이 아니라 이전 노드가 가리키는 대상을 바꾸는 일입니다. 삭제하려는 노드가 머리라면 머리 참조를 다음 노드로 옮겨야 하고, 빈 리스트나 마지막 노드 뒤를 삭제하려는 요청도 안전하게 처리해야 합니다. 외부 코드가 삭제된 노드의 참조를 계속 보관할 수 있는 언어에서는 그 노드의 `next`를 비우는 것이 객체 상태를 분명하게 만드는 데 도움이 될 수 있습니다.

![연결 리스트에서 노드를 삭제하는 예](linked_list.assets/linkedlist_remove_node.png)

```python
class ListNode:
    def __init__(self, value: int):
        self.value = value
        self.next: ListNode | None = None


def remove_after(n0: ListNode) -> None:
    if n0.next is None:
        return
    n0.next = n0.next.next
```

### 노드 접근

배열은 임의 원소에 $O(1)$ 시간으로 접근하지만 연결 리스트는 인덱스로 주소를 직접 계산할 수 없습니다. $i$번째 노드를 얻으려면 머리 노드에서 시작해 $i - 1$개의 연결을 하나씩 따라가야 하므로 접근 복잡도는 $O(n)$입니다.

```python
class ListNode:
    def __init__(self, value: int):
        self.value = value
        self.next: ListNode | None = None


def access(head: ListNode | None, index: int) -> ListNode | None:
    for _ in range(index):
        if head is None:
            return None
        head = head.next
    return head
```

### 노드 검색

값이 `target`인 노드를 찾는 것도 선형 탐색입니다.

각 노드의 값이 목표와 같은지 차례대로 비교하며, 일치하는 노드를 만나면 현재 위치를 반환합니다. 목표가 없으면 꼬리 뒤의 빈 참조까지 방문해야 하므로 최악의 경우 리스트 전체 길이에 비례합니다.

연결 리스트에는 다음 노드 주소를 계산하는 공식이 없기 때문에 탐색 도중의 노드를 건너뛸 수 없습니다. 정렬된 연결 리스트라 해도 중간 인덱스로 즉시 이동할 수 없으므로 배열에서 사용하는 일반적인 이진 탐색의 장점을 그대로 얻기 어렵습니다. 자주 검색해야 한다면 해시 테이블이나 트리 같은 별도의 색인 구조를 함께 사용하는 편이 나을 수 있습니다.

```python
class ListNode:
    def __init__(self, value: int):
        self.value = value
        self.next: ListNode | None = None


def find(head: ListNode | None, target: int) -> int:
    index = 0
    while head is not None:
        if head.value == target:
            return index
        head = head.next
        index += 1
    return -1
```

## 배열과 연결 리스트 비교

| 특성 | 배열 | 연결 리스트 |
| --- | --- | --- |
| 저장 방식 | 연속 메모리 | 분산 메모리 |
| 확장 | 길이가 고정되고 확장 시 복사 필요 | 노드 단위로 유연하게 조절 |
| 메모리 효율 | 구조 비용은 작지만 남는 용량이 생길 수 있음 | 각 노드에 추가 연결 필요 |
| 원소 접근 | $O(1)$ | $O(n)$ |
| 위치를 아는 경우 뒤에 삽입 | 보통 $O(n)$ | $O(1)$ |
| 위치를 아는 경우 뒤의 원소 삭제 | 보통 $O(n)$ | $O(1)$ |

연결 리스트 삽입과 삭제의 `O(1)` 복잡도는 연산할 위치의 참조를 이미 가지고 있다고 가정합니다. 먼저 위치를 찾아야 한다면 전체 과정은 여전히 `O(n)`이 될 수 있습니다.

따라서 작업 패턴이 중요합니다. 머리나 꼬리처럼 참조를 계속 보관하는 위치에서 자주 삽입·삭제한다면 연결 리스트의 이점을 얻기 쉽습니다. 반대로 임의의 순번을 자주 읽어야 한다면 매번 순회가 필요해 배열보다 불리합니다.

메모리 관점에서도 단순히 “연결 리스트는 필요한 만큼만 만든다”는 설명만으로는 충분하지 않습니다. 배열은 미사용 용량이 생길 수 있지만 각 원소에 연결 정보를 저장하지 않습니다. 연결 리스트는 빈 용량을 미리 예약하지 않는 대신 모든 노드가 참조와 객체 관리 정보를 추가로 가집니다. 값이 작은 경우에는 이 부가 정보가 실제 데이터보다 더 많은 공간을 차지할 수도 있습니다. 또한 연속된 배열은 순차 접근에서 캐시를 잘 활용하지만 흩어진 노드는 매번 다른 캐시 라인을 요구할 수 있습니다.

## 연결 리스트의 종류

- **단일 연결 리스트**: 각 노드가 값과 다음 노드의 연결을 저장하고 꼬리 노드는 `None`을 가리킵니다.
- **원형 연결 리스트**: 꼬리 노드가 머리 노드를 다시 가리킵니다. 어느 노드든 시작점으로 볼 수 있습니다.
- **이중 연결 리스트**: 각 노드가 이전 노드와 다음 노드의 연결을 모두 저장합니다. 양방향 순회가 가능하지만 메모리를 더 사용합니다.

원형 연결 리스트에서는 빈 참조가 끝을 표시하지 않으므로 시작 노드로 다시 돌아왔는지를 검사해 순회를 종료해야 합니다. 이중 연결 리스트는 어느 노드를 삭제할 때 앞뒤 노드의 연결을 모두 바꾸어야 하며, 두 방향의 참조가 서로 일치한다는 불변식을 유지해야 합니다. 기능이 늘어날수록 갱신해야 하는 연결 수와 구현 복잡도도 함께 늘어납니다.


## 대표적인 활용

단일 연결 리스트는 다음 구조에서 자주 사용됩니다.

- **스택과 큐**: 어느 끝에서 추가하고 삭제하는지에 따라 후입선출 또는 선입선출 동작을 만듭니다.
- **해시 테이블**: 체이닝 방식은 충돌한 원소를 연결 리스트에 저장합니다.
- **그래프**: 인접 리스트에서 각 정점은 이웃 정점 목록과 연결됩니다.

이중 연결 리스트는 앞뒤 원소에 빠르게 접근해야 할 때 적합합니다.

- 트리에서 부모 참조 저장
- 브라우저의 앞으로 가기와 뒤로 가기 기록
- 노드의 추가, 삭제, 이동이 빨라야 하는 LRU 캐시 제거 알고리즘

원형 연결 리스트는 주기적으로 반복하는 작업에 적합합니다.

- 운영체제의 라운드 로빈 스케줄링
- 오디오나 비디오 스트림의 순환 버퍼 관리

응용 구조에서는 필요한 연산에 맞춰 머리와 꼬리 참조를 함께 저장하기도 합니다. 예를 들어 큐가 꼬리 참조를 유지하면 새 노드를 넣기 위해 매번 끝까지 탐색하지 않아도 됩니다. 이중 연결 리스트와 해시 테이블을 결합한 LRU 캐시는 키로 노드를 즉시 찾고, 앞뒤 연결을 바꾸어 최근 사용 순서를 빠르게 갱신합니다. 즉 연결 리스트의 성능상 이점은 노드 위치를 빠르게 얻는 다른 장치와 결합될 때 더욱 분명해집니다.

연결 리스트는 크기를 유연하게 바꾸고 알려진 위치의 연결을 빠르게 수정할 수 있지만, 참조를 위한 추가 공간과 낮은 캐시 지역성이라는 비용을 지닙니다. 실제 선택에서는 연산 복잡도뿐 아니라 메모리 배치와 접근 패턴도 함께 살펴야 합니다.
