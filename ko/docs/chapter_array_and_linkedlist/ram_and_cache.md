# 임의 접근 메모리와 캐시 *

배열과 연결 리스트는 연속 저장과 분산 저장이라는 두 물리 배치를 대표합니다. **물리 배치는 RAM과 캐시의 사용 효율에 큰 영향을 주며**, 결과적으로 프로그램 성능도 달라집니다.

## 저장 장치

컴퓨터에는 디스크, RAM, CPU 캐시라는 세 가지 중요한 저장 계층이 있습니다.

디스크는 전원이 꺼져도 데이터를 유지하는 비휘발성 장치로 운영체제, 프로그램, 문서를 장기간 보관합니다. RAM은 실행 중인 프로그램의 코드와 데이터를 임시로 담는 작업 공간입니다. CPU 캐시는 RAM에서 자주 사용할 일부 데이터와 명령을 복사해 프로세서 가까이에 둡니다. 세 장치는 같은 데이터를 서로 다른 시점에 담을 수 있지만 목적과 성능 특성이 다릅니다.

| 특성 | 디스크 | RAM | 캐시 |
| --- | --- | --- | --- |
| 목적 | 운영체제, 프로그램, 파일의 장기 저장 | 실행 중인 프로그램과 처리 중인 데이터의 임시 저장 | 자주 접근하는 데이터와 명령을 CPU 가까이에 저장 |
| 전원이 꺼질 때 | 데이터 유지 | 데이터 소실 | 데이터 소실 |
| 용량 | 크며 보통 TB 단위 | 더 작고 보통 GB 단위 | 매우 작고 보통 MB 단위 |
| 속도 | 가장 느림 | 빠름 | 가장 빠름 |
| GB당 비용 | 낮음 | 더 높음 | 매우 높고 보통 CPU에 포함됨 |

저장 계층은 피라미드처럼 생각할 수 있습니다. CPU에 가까운 계층일수록 빠르고 작으며 비쌉니다.

이 계층이 필요한 이유는 하나의 저장 장치가 큰 용량, 영구 보존, 매우 짧은 접근 시간을 동시에 경제적으로 제공하기 어렵기 때문입니다. 자주 쓰는 작은 부분은 빠른 계층에 두고, 나머지는 더 크고 느린 계층에 두어 전체 시스템의 비용과 속도를 균형 있게 맞춥니다. 프로그램이 같은 데이터를 반복해서 사용할수록 상위 계층에 남아 있을 가능성이 높아져 평균 접근 시간이 줄어듭니다.

CPU가 매 연산마다 디스크를 직접 기다린다면 계산 장치 대부분이 유휴 상태가 됩니다. RAM은 디스크보다 훨씬 빠른 중간 계층을 제공하고, 캐시는 RAM과 CPU 사이의 속도 차이를 다시 줄입니다. 프로그램은 이 계층 구조를 직접 모두 제어하지 않더라도 데이터 배치와 접근 순서를 통해 활용 효율에 큰 영향을 줍니다.

- 디스크를 RAM으로 완전히 대체할 수는 없습니다. RAM은 전원이 끊기면 데이터가 사라지고 훨씬 비쌉니다.
- 캐시는 동시에 매우 크고 매우 빠를 수 없습니다. 용량과 물리적 거리가 늘면 지연도 커집니다. L1, L2, L3 같은 여러 계층은 속도, 용량, 비용 사이의 균형입니다.

![컴퓨터 저장 계층 피라미드](ram_and_cache.assets/storage_pyramid.png)

!!! tip

    저장 계층은 속도, 용량, 비용 사이의 대표적인 트레이드오프를 보여 줍니다. 비슷한 선택은 거의 모든 공학 시스템에 나타납니다. 한 특성을 극대화하면 다른 특성의 비용이 커지는 경우가 많으므로 사용 목적에 맞는 균형이 필요합니다.

디스크는 장기 데이터를 저장하고 RAM은 실행 중인 프로그램의 데이터를 보관하며 캐시는 자주 접근하는 데이터와 명령 일부를 저장합니다. 프로그램이 실행되면 데이터가 디스크에서 RAM으로 이동합니다. 캐시는 CPU가 더 빨리 접근할 수 있도록 RAM의 데이터를 미리 가져옵니다.

CPU가 요청한 데이터가 캐시에 있으면 매우 빠르게 읽을 수 있습니다. 캐시에 없으면 RAM에서 가져와야 하고, RAM에도 없다면 운영체제가 디스크에서 페이지를 불러오는 훨씬 느린 작업이 필요할 수 있습니다. 따라서 같은 계산량을 가진 프로그램이라도 메모리 접근 패턴에 따라 실제 실행 시간이 크게 달라집니다.

프로그램 시작 시 실행 파일과 필요한 데이터가 디스크에서 RAM으로 적재되고, CPU가 명령과 값을 요청하면 하드웨어가 그 일부를 캐시에 복사합니다. 각 계층은 바로 아래 계층의 일부를 임시로 보관하는 셈입니다. 필요한 데이터가 가까운 계층에 없을 때에는 더 느린 계층에서 가져오는 동안 지연이 발생하므로, 계산 명령 수만 세어서는 전체 실행 시간을 정확히 예측하기 어렵습니다.

## 자료구조의 메모리 효율

배열과 연결 리스트는 서로 다른 장점을 가집니다.

- 배열 원소는 서로 붙어 있고 연결을 저장하지 않아 구조 비용이 낮습니다. 하지만 충분히 큰 연속 공간이 필요하고 남는 용량이 생길 수 있으며 확장할 때 시간과 공간이 듭니다.
- 연결 리스트는 노드 단위로 할당하고 해제하므로 유연하지만 각 노드가 추가 연결을 저장해야 합니다.

배열은 시작 주소와 원소 수를 관리하면 되므로 원소마다 별도 구조 정보를 거의 두지 않습니다. 반면 연결 리스트는 모든 노드에 다음 노드, 경우에 따라 이전 노드에 대한 참조를 저장합니다. 값 자체가 작을수록 이 참조의 상대적 비용은 더 커집니다. 메모리 할당자가 노드마다 정렬과 관리 정보를 추가할 수도 있습니다.

배열에 실제 원소 수보다 큰 용량을 예약하면 사용하지 않는 칸이 생기지만, 연결 리스트도 항상 공간 효율적인 것은 아닙니다. 참조 필드, 객체 헤더, 할당 단위 때문에 전체 사용량이 배열보다 커질 수 있습니다. 어떤 낭비가 더 큰지는 값의 크기, 확장 전략, 할당자와 실행 환경에 따라 달라집니다.

배열의 확장 시점에는 기존 배열과 새 배열이 잠시 동시에 존재할 수 있어 순간적인 메모리 사용량도 증가합니다. 반면 연결 리스트는 노드를 하나씩 만들 수 있지만 각 할당마다 관리 오버헤드가 붙을 수 있습니다. 그래서 평균 사용량뿐 아니라 최대 사용량, 할당 횟수, 객체 수명도 함께 측정해야 합니다. 작은 원소를 매우 많이 저장할수록 노드별 부가 비용의 영향이 커집니다.

메모리를 반복해서 할당하고 해제하면 빈 공간이 점점 조각납니다. 연속 저장 배열은 보통 단편화를 덜 일으키고, 흩어진 노드가 자주 바뀌는 연결 리스트는 단편화에 더 많이 기여할 수 있습니다.

단편화가 심하면 사용 가능한 전체 메모리는 충분해도 큰 연속 블록을 찾지 못할 수 있습니다. 배열 확장은 큰 새 블록을 요구하므로 이 상황의 영향을 받습니다. 연결 리스트는 작은 블록을 활용할 수 있지만 많은 개별 할당과 해제가 관리 비용을 늘립니다. 자료구조의 유연성과 할당 비용을 함께 고려해야 합니다.

## 캐시 효율

캐시는 RAM보다 작지만 훨씬 빠릅니다. CPU가 필요로 하는 데이터가 캐시에 없으면 **캐시 미스**가 발생하여 RAM에서 데이터를 가져와야 합니다. CPU가 캐시에서 바로 데이터를 찾는 비율을 **캐시 적중률**이라고 합니다.

캐시 적중률이 높을수록 CPU가 느린 메모리를 기다리는 시간이 줄어듭니다. 이 효과는 빅오 복잡도에는 드러나지 않지만 실제 성능에서는 매우 중요합니다. 같은 수의 원소를 같은 횟수만큼 처리해도 접근 주소가 연속적인지 무작위인지에 따라 캐시 미스 수가 달라집니다.

캐시는 다음 메커니즘을 활용합니다.

- **캐시 라인**: 데이터는 개별 바이트가 아니라 일정 크기의 블록으로 전송됩니다.
- **프리페치**: 프로세서가 순차 접근이나 고정 간격 같은 패턴을 예측해 데이터를 미리 불러옵니다.
- **공간 지역성**: 한 위치에 접근하면 가까운 데이터도 곧 사용될 가능성이 큽니다.
- **시간 지역성**: 방금 사용한 데이터가 가까운 미래에 다시 사용될 가능성이 큽니다.

캐시 라인은 요청한 바이트 주변을 한 번에 가져와 공간 지역성을 활용합니다. 프리페처는 순차적이거나 일정 간격인 접근 패턴을 감지해 다음 라인을 미리 요청합니다. 시간 지역성이 높은 데이터는 다른 데이터에 밀려나기 전에 반복 사용되어 캐시 적중을 얻습니다.

예를 들어 배열을 처음부터 끝까지 읽으면 첫 원소를 요청할 때 같은 캐시 라인에 들어 있는 뒤쪽 원소도 함께 도착합니다. 다음 원소를 읽을 때 이미 캐시에 있을 가능성이 높고, 하드웨어는 일정한 주소 증가를 보고 다음 라인까지 미리 요청할 수 있습니다. 같은 배열이라도 큰 간격으로 뛰어다니거나 무작위 순서로 접근하면 가져온 라인의 많은 부분을 사용하지 않아 이 장점이 줄어듭니다.

배열은 보통 연결 리스트보다 캐시를 잘 활용합니다.

- 연결 리스트 노드는 참조를 추가로 저장해 더 크므로 한 캐시 라인에 유용한 데이터가 적게 들어갑니다.
- 노드가 흩어져 있어 한 번 불러온 캐시 라인에 관련 없는 데이터가 많이 포함될 수 있습니다.
- 배열의 접근 패턴은 예측하기 쉽습니다.
- 배열의 연속 메모리는 공간 지역성이 좋습니다.

연결 리스트에서는 다음 노드 주소를 현재 노드를 읽은 뒤에야 알 수 있어 여러 메모리 요청을 미리 병렬로 준비하기 어렵습니다. 노드가 서로 다른 캐시 라인에 흩어져 있으면 각 방문마다 새 라인을 불러와야 할 수 있습니다. 반면 배열 순회는 다음 주소가 규칙적이므로 하드웨어가 미리 읽기 쉽습니다.

이 차이는 두 순회가 모두 선형 시간 복잡도를 가진다는 사실만으로는 나타나지 않습니다. 빅오 표기는 입력이 커질 때 연산 수가 증가하는 비율을 설명하지만 메모리 대기 시간이나 한 번에 전송되는 바이트 수는 감춥니다. 실제 하드웨어에서는 같은 차수의 알고리즘도 캐시 적중률, 분기 예측, 메모리 할당 방식에 따라 큰 상수 배수 차이를 보일 수 있습니다.

따라서 배열은 보통 캐시 적중률과 실제 성능이 더 좋습니다. 그렇다고 배열이 언제나 우수한 것은 아닙니다. 데이터가 매우 크고 자주 변하며 용량을 예측하기 어렵다면 연결 리스트 기반 구조가 큰 연속 공간 요구와 배열 확장 비용을 피할 수 있습니다.

최종 선택은 이론적 연산 횟수, 값의 크기, 데이터 증가 방식, 순회 빈도와 하드웨어 특성을 함께 반영해야 합니다. 성능이 중요한 경로에서는 실제 입력을 사용한 측정으로 가정을 확인하는 것이 가장 안전합니다.

측정할 때에는 현실적인 데이터 크기와 접근 순서를 사용하고, 준비 단계와 핵심 연산의 시간을 구분해야 합니다. 작은 예제에서는 모든 데이터가 캐시에 들어가 두 구조의 차이가 보이지 않을 수 있고, 지나치게 인위적인 벤치마크는 실제 서비스의 할당과 접근 패턴을 반영하지 못할 수 있습니다. 이론적 분석으로 후보를 좁힌 뒤 재현 가능한 실험으로 확인하는 과정이 바람직합니다.
