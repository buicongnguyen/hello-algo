# 분할 정복 알고리즘

<u>분할 정복</u>은 매우 중요하고 널리 쓰이는 알고리즘 설계 전략입니다. 보통 재귀를 바탕으로 구현하며, “분할”과 “정복”의 두 단계로 이루어집니다.

1. **분할(나누는 단계)**: 원래 문제를 둘 이상의 더 작은 부분 문제로 재귀적으로 나누어, 해를 이미 알 수 있는 가장 작은 문제까지 내려갑니다.
2. **정복(합치는 단계)**: 가장 작은 부분 문제의 해에서 시작하여, 아래에서 위로 부분 해를 결합해 원래 문제의 해를 만듭니다.

재귀 관점에서 분할은 호출 트리를 아래로 내려가는 과정이고, 정복은 반환값이 위로 올라오는 과정입니다. 각 호출은 현재 문제의 범위와 “무엇을 반환해야 하는가”라는 동일한 계약을 지닙니다. 종료 조건은 더 나눌 필요가 없는 최소 문제를 정의하며, 결합 규칙은 두 부분 해가 원래 계약을 다시 만족하도록 만듭니다.

아래 그림의 병합 정렬은 분할 정복을 대표적으로 보여 줍니다.

1. **분할**: 원래 배열을 두 부분 배열로 계속 나누고, 부분 배열에 원소가 하나만 남으면 멈춥니다.
2. **정복**: 이미 정렬된 부분 배열을 아래에서 위로 병합하여 전체 정렬 배열을 얻습니다.

## 분할 정복 문제를 판별하는 방법

문제가 분할 정복에 적합한지는 대개 다음 세 조건으로 판단할 수 있습니다.

1. **문제를 분해할 수 있음**: 원래 문제를 형태가 같은 더 작은 문제로 나눌 수 있고, 같은 방법으로 재귀적인 분해가 가능합니다.
2. **부분 문제가 서로 독립적임**: 부분 문제 사이에 중복이 없고, 한 부분의 해를 다른 부분의 계산 없이 구할 수 있습니다.
3. **부분 문제의 해를 결합할 수 있음**: 부분 해를 모아 원래 문제의 해를 만들 수 있습니다.

병합 정렬은 세 조건을 모두 만족합니다.

1. 배열을 두 부분 배열로 반복해 나눌 수 있습니다.
2. 두 부분 배열은 서로 독립적으로 정렬할 수 있습니다.
3. 두 정렬 배열을 병합하면 원래 배열의 정렬 결과를 얻습니다.

이 기준은 단순히 “재귀를 쓸 수 있는가”를 묻는 것이 아닙니다. 분해한 문제가 원래 문제와 같은 구조인지, 중복 계산이 생기지 않는지, 그리고 부분 해를 정확하고 효율적으로 결합할 수 있는지를 함께 확인해야 합니다.

부분 문제가 크게 겹친다면 같은 계산이 여러 번 반복될 수 있습니다. 이런 경우에는 메모이제이션이나 동적 계획법이 더 자연스러울 수 있습니다. 반대로 부분 문제는 독립적이지만 결합 단계가 원래 문제보다 더 비싸다면 분할의 이점이 사라집니다. 따라서 입력을 나누는 행위 자체가 아니라, 분해와 해결과 결합을 모두 포함한 전체 비용을 비교해야 합니다.

## 분할 정복으로 효율 높이기

**분할 정복은 문제를 효과적으로 해결할 뿐 아니라 알고리즘의 효율도 높이는 경우가 많습니다.** 정렬에서는 퀵 정렬, 병합 정렬, 힙 정렬이 선택·버블·삽입 정렬보다 빠른 경우가 많은데, 문제의 규모를 단계적으로 줄이는 분할 정복 사고가 중요한 역할을 합니다.

그렇다면 큰 문제를 직접 푸는 것보다 작은 문제로 나누고 각각을 푼 뒤 합치는 편이 왜 더 효율적일까요? 연산 횟수와 병렬 계산의 두 관점에서 살펴볼 수 있습니다.

균형 잡힌 분할은 재귀 트리의 높이를 낮추고 각 층의 일을 예측하기 쉽게 합니다. 한쪽 부분만 계속 크게 남는 불균형 분할은 문제 크기를 충분히 줄이지 못해 재귀가 깊어질 수 있습니다. 따라서 실제 알고리즘에서는 분할 가능 여부뿐 아니라 부분 문제 크기의 균형과 결합 비용도 중요한 설계 요소입니다.

### 연산 횟수 최적화

버블 정렬을 예로 들면 길이 $n$인 배열을 처리하는 데 $O(n^2)$ 시간이 걸립니다. 배열을 중앙에서 두 부분으로 나누면 분할에 $O(n)$, 각 부분을 정렬하는 데 $O((n / 2)^2)$, 두 부분을 병합하는 데 $O(n)$ 시간이 듭니다. 전체 시간은 다음과 같습니다.

$$
O(n + (\frac{n}{2})^2 \times 2 + n) = O(\frac{n^2}{2} + 2n)
$$

![배열을 나누기 전후의 버블 정렬](divide_and_conquer.assets/divide_and_conquer_bubble_sort.png)

분할 전후의 총 연산 수를 비교하면 다음 부등식을 얻습니다.

$$
\begin{aligned}
n^2 & > \frac{n^2}{2} + 2n \\
n^2 - \frac{n^2}{2} - 2n & > 0 \\
n(n - 4) & > 0
\end{aligned}
$$

따라서 **$n > 4$이면 분할한 뒤의 연산 수가 더 적어 정렬 효율이 높아집니다.** 이 한 번의 분할만으로는 여전히 이차 시간 $O(n^2)$이지만, 숨은 상수는 작아졌습니다.

부분 배열의 길이가 하나가 될 때까지 중앙에서 계속 나누면 병합 정렬이 됩니다. 이때 시간 복잡도는 $O(n \log n)$으로 낮아집니다.

더 나아가 여러 분할점을 두고 원래 배열을 $k$개의 부분으로 고르게 나누면 버킷 정렬과 비슷한 구조가 됩니다. 버킷 정렬은 대규모 데이터에 적합하며 이상적인 분포에서는 $O(n + k)$의 시간 복잡도를 가집니다.

분할 자체와 결합 비용도 반드시 계산해야 합니다. 부분 문제만 작아져도 분할·결합이 지나치게 비싸거나 부분 문제가 크게 겹치면 전체 효율은 좋아지지 않을 수 있습니다.

한 번 나누는 예는 숨은 상수를 줄이는 효과를 보여 주지만, 점근 차수를 낮추려면 같은 유리한 분해가 여러 단계에서 반복되어야 합니다. 병합 정렬은 각 단계에서 구간을 균형 있게 줄이고, 각 층에서 모든 원소를 일정 횟수만 처리합니다. 버킷 정렬은 값의 분포가 고른지를 추가 가정으로 사용합니다. 분포가 한 버킷에 몰리면 이론적인 이점이 줄어들므로 입력 특성까지 확인해야 합니다.

### 병렬 계산 최적화

분할 정복으로 만든 부분 문제는 서로 독립적인 경우가 많으므로 **동시에 해결할 수 있습니다**. 따라서 분할 정복은 연산 수를 줄이는 데 그치지 않고 운영체제나 실행 환경의 병렬 처리에도 잘 맞습니다.

다중 코어나 다중 프로세서 환경에서는 여러 계산 장치가 서로 다른 부분 문제를 동시에 처리할 수 있습니다. 충분히 큰 문제를 균형 있게 나누고 동기화·통신 비용을 제어하면 자원을 더 잘 활용하고 전체 실행 시간을 줄일 수 있습니다.

다만 부분 문제를 만드는 비용, 작업을 다른 장치로 보내는 비용, 마지막 결과를 기다리고 합치는 비용은 사라지지 않습니다. 지나치게 작은 작업을 많이 만들면 병렬 실행의 관리 비용이 실제 계산보다 커질 수 있습니다. 실무에서는 일정 크기 이하의 부분 문제를 한 작업 안에서 순차 처리하고, 큰 문제만 병렬로 분기하는 임계값을 두는 경우가 많습니다.

아래 버킷 정렬에서는 대량의 데이터를 여러 버킷에 고르게 분배합니다. 각 버킷의 정렬 작업을 별도 계산 장치에 맡기고, 모든 정렬이 끝난 뒤 결과를 순서대로 결합할 수 있습니다.

## 분할 정복의 주요 활용

분할 정복은 여러 고전 알고리즘 문제를 해결하는 데 사용됩니다.

- **가장 가까운 두 점 찾기**: 점 집합을 두 부분으로 나누어 각 부분의 최근접 쌍을 구한 뒤, 경계를 가로지르는 쌍까지 비교합니다.
- **큰 정수 곱셈**: 카라추바 알고리즘은 큰 수의 곱셈을 더 작은 곱셈과 덧셈으로 분해합니다.
- **행렬 곱셈**: 스트라센 알고리즘은 큰 행렬 곱셈을 여러 작은 행렬 곱셈과 덧셈으로 나눕니다.
- **하노이 탑**: 재귀로 해결하는 전형적인 분할 정복 문제입니다.
- **역순 쌍 계산**: 앞의 수가 뒤의 수보다 큰 쌍을 병합 정렬 과정에서 효율적으로 셀 수 있습니다.

이 문제들은 결합 방식이 서로 다릅니다. 최근접 점 쌍은 두 영역을 가로지르는 후보를 추가로 확인하고, 카라추바와 스트라센은 대수식을 재배열해 필요한 곱셈 수를 줄이며, 역순 쌍은 두 정렬 구간을 병합할 때 교차 쌍을 셉니다. 공통점은 부분 해만 계산하는 데 그치지 않고 경계를 가로지르는 정보를 정확히 처리한다는 것입니다.

분할 정복 사고는 알고리즘과 자료 구조 설계 전반에도 스며 있습니다.

- **이진 탐색**: 중앙값과 목표를 비교해 정렬 배열의 절반을 제거하고, 남은 구간에 같은 절차를 적용합니다.
- **병합 정렬**: 배열을 독립적인 부분으로 나눈 뒤 정렬된 결과를 병합합니다.
- **퀵 정렬**: 피벗을 기준으로 작은 원소와 큰 원소의 두 구간을 만들고 각 구간을 같은 방식으로 처리합니다.
- **버킷 정렬**: 데이터를 여러 버킷에 흩어 각 버킷을 정렬하고 차례대로 꺼냅니다.
- **트리**: 이진 탐색 트리, AVL 트리, 레드-블랙 트리, B 트리와 B+ 트리의 탐색·삽입·삭제는 문제 범위를 하위 트리로 줄입니다.
- **힙**: 완전 이진 트리의 경로를 따라 삽입, 삭제, 힙화를 수행하는 과정에 분할 정복 관점이 들어 있습니다.
- **해시 테이블**: 직접적인 분할 정복 구조는 아니지만, 체이닝의 긴 연결 리스트를 레드-블랙 트리로 바꾸는 충돌 처리처럼 간접적으로 관련 전략을 사용합니다.

이처럼 **분할 정복은 눈에 띄지 않게 곳곳에 존재하는 설계 사고**이며, 문제를 독립적인 단위로 줄이고 다시 결합할 수 있는지 보는 관점을 제공합니다.

새 문제를 만났을 때는 먼저 최소 문제의 해를 정의하고, 현재 문제를 같은 계약의 더 작은 문제로 표현한 뒤, 반환된 부분 해에서 원래 해를 만드는 규칙을 써 보는 것이 좋습니다. 그 다음 재귀 깊이, 각 층의 총 작업, 추가 메모리와 병렬화 가능성을 분석하면 구현과 복잡도 설명이 서로 일치하는지 검증할 수 있습니다.

마지막으로 작은 입력과 경계 조건을 손으로 추적해 보세요. 분할 구간이 빠짐없이 전체 입력을 덮는지, 서로 겹치지 않는지, 최소 문제에서 반드시 종료하는지, 결합 뒤의 결과가 호출 계약을 만족하는지 확인하면 재귀 경계 오류를 일찍 발견할 수 있습니다.
